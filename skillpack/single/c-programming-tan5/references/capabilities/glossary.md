# 术语速查（C 程序设计核心概念）

## R — 原文

> "所谓类型，就是对数据分配存储单元的安排，包括存储单元的长度（占多少字节）以及数据的存储形式。"
> ——第3章 §3.2.2 数据类型

> "要区别指针和指针变量。指针就是地址，而指针变量是用来存放地址的变量。"
> ——第8章 §8.9

> "符号常量不占内存，只是一个临时符号，代表一个值，在预编译后这个符号就不存在了，故不能对符号常量赋新值。"
> ——第3章 §3.2.1

## I — 自述

这本书的术语体系有一个特点：多个词看起来相近，但作者给了严格区分，混淆它们就是很多误解的源头。最典型的三组是：

**「指针 / 指针变量 / 基类型」** —— 指针是地址（一个值），指针变量是存地址的变量，基类型说明它指向什么类型的数据。三者混着说，后面的数组指针、函数指针全都会乱。

**「常量 / 符号常量 / 常变量」** —— 常量是字面值（不占变量空间）；符号常量是 `#define` 出来的名字，预编译后就被替换掉、**不占存储单元**、不能赋值；常变量是 `const` 定义的，**占存储单元**、有类型，只是值不许改。三者的关键差异是"占不占空间"和"能不能被替换"。

**「定义 / 声明」** —— 定义会分配空间（对变量）或给出实现（对函数）；声明只是告诉编译器"有这么个东西、它是什么规格"，不分配空间。函数原型是声明，函数体是定义。

另外几个高频易混点：

- **「数组有序」** 指有下标次序，不是"已排序"；
- **「判断框两出口」** 是图形事实，但**选择结构整体只有一个出口**；
- **「值传递」** 是单向的，形参改动不影响实参；但数组名作参数时传的是地址，所以函数内能改原数组——这不矛盾，传的"值"就是地址；
- **「目标程序 / 可执行程序」** 是编译产物与连接产物的区别，中间隔着一个连接步骤；
- **「缓冲区」** 的存在解释了为什么文件不 `fclose` 会丢数据。

下表按主题归拢全书核心术语，每条标注出处，便于回原文核对。

## A1 — 书中案例

术语的精确性直接决定程序对错，书中有两处对照最能说明：

- **符号常量 vs 常变量（§3.2.1）**：`#define Pi 3.1415926` 与 `const float pi=3.1415926;` 都代表同一个值、都能在程序里用，但符号常量在预编译后就不存在了、不分配存储单元；常变量要占用存储单元、有变量值。原书结论是"有了常变量以后，可以不必多用符号常量"。
- **指针 vs 指针变量（§8.1 / §8.9）**：可以说"变量 i 的指针是 2000"，不能说"i 的指针变量是 2000"。原书强调"不要杜撰出'地址的值'这样莫须有的名词"——地址本身就是一个值。

## A2 — 何时触发

用户会在这些情境下：
- 读教材/文档时被某个术语卡住，想快速搞清它到底指什么；
- 两个相近词分不清（指针 vs 指针变量、常量 vs 常变量、定义 vs 声明、数组 vs 指针）；
- 想确认某个说法是否准确（"数组名是不是指针"）；
- 写代码时不确定某个概念在 C 里的确切边界。

语言信号：「XX 是什么意思」「A 和 B 有什么区别」「数组名是指针吗」「define 和 const 有什么区别」「声明和定义」「形参和实参」「目标程序和可执行程序」「'\0' 是什么」「EOF 是什么」。

**与相邻能力区分**：本能力只管「概念澄清」。如果用户问完概念后要动手写代码，应转到对应能力：骨架 → `program-skeleton`；算法 → `algorithm-design`；控制语句 → `control-flow`；数组 → `array-and-string`；函数 → `function-and-recursion`；指针 → `pointer-model`；结构体 → 《结构体与链表》能力卡；文件 → 《文件读写》能力卡。

## E — 执行步骤

**输入契约**：需要用户指出具体术语（或描述"我想问 X 和 Y 的区别"）。若只给一个含糊说法（如"那个地址的东西"），先确认对应术语名，不要猜。

**输出契约**：交付「作者定义（尽量引原文）→ 出处章节 → 与常识/近邻概念的差异 → 一个最小代码示例」。若术语在原书未定义，明确标注"原书未定义，以下为通用定义"。

步骤：

1. **定位术语**：在本卡表格中查找。完成标准：命中一条，或判定"原书未收该术语"。
2. **给出定义与出处**：引用作者原话（不超过 150 字）并标注章节。完成标准：用户可回原文核对。
3. **点明差异**（关键）：说明它与最容易被混淆的近邻概念差在哪。完成标准：至少给出一条"如果混淆会导致什么错误"。
4. **给最小示例**：用两三行代码或一个对比演示差异（如 `#define` 与 `const` 各写一行）。完成标准：示例能直接说明差异，不引入无关内容。
5. **判定是否需要转能力**（判停点）：若用户接着问"那怎么写"，转 A2 中列出的对应能力，不在本卡里展开教学。

## B — 边界

- **不适用**：用户要的是完整教程或系统讲解，而不是单点澄清——应转到对应能力卡，本卡只做速查。
- **作者盲点**（阶段 0 批判）：本书基于 C89/C99，部分术语的边界在现代 C 中已扩展（如 C99 引入 `bool`、变长数组、`//` 注释正式纳入标准、`const` 的语义细节）。表中已尽量标注，遇到现代标准差异时应明确告知。
- **易混淆（本卡自身）**：不要把"术语速查"当成"概念教学"——速查给的是边界，不是理解过程；用户若反复卡在同一个概念上，说明需要的是 `pointer-model` 这类深入讲解，而非更多定义。
- **失败模式**：脱离上下文解释术语，导致"每个字都懂、合起来还是不懂"。必须给示例。
