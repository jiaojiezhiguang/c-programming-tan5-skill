# 结构体与链表

## R — 原文

> "结构体类型与结构体变量是不同的概念，不要混淆。只能对变量赋值、存取或运算，而不能对一个类型赋值、存取或运算。在编译时，对类型是不分配空间的，只对变量分配空间。"
> ——第9章 §9.1 定义和使用结构体变量

> "如果将 num,name,sex,age,score 和 addr 分别定义为互相独立的简单变量，难以反映它们之间的内在联系。人们希望把这些数据组成一个组合数据……"
> ——第9章 §9.1.1 自己建立结构体类型

> "【例9.8】建立一个如图9.9所示的简单链表，它由3个学生数据的结点组成，要求输出各结点中的数据。"
> ——第9章 §9.4

## I — 自述

系统提供的基本类型（`int`、`float`、`char`）只能描述孤立的数据。但现实中的一组数据往往是有内在联系的——一个学生的学号、姓名、性别、年龄、成绩、地址属于同一个人，用 6 个互不相干的变量存，丢掉了"它们属于同一个实体"这个信息。数组也不行：数组只能装同一类型的数据，装得下学号装不下姓名。**结构体**就是为这种"由不同类型成员组成的组合数据"准备的。

理解结构体要抓住「类型」与「变量」的严格区分：`struct Student` 是**类型**（一个样板，编译时不占空间），`struct Student s1` 才是**变量**（占空间、能存取、能赋值）。所以"给 `struct Student` 赋值"是非法的——类型只是用来定义变量的模板。

成员用 `.` 访问（`s1.num`），通过指针访问时用 `->`（`p->num` 等价于 `(*p).num`）。

结构体最有价值的用法是**自引用结构**——结构体的成员可以是指向**自身类型**的指针。这正是链表的根基：每个结点有数据域（存数据）和指针域（存下一个结点的地址），用指针把分散的结点串起来。这带来数组完全不具备的能力：长度可以在运行期动态增长、插入删除不必整体搬移。

链表的三条要点：①结点用 `malloc` 逐个动态分配；②每个结点的 `next` 指向下一个结点，**尾结点的 `next` 必须置 `NULL`**，这是遍历的终止标志；③遍历写成 `for(p=head; p!=NULL; p=p->next)`。忘了置 `NULL`，遍历就会越过末尾继续读垃圾内存。

## A1 — 书中案例

- **例9.3 统计选票（原书给出程序结构）**：3 个候选人，输入被选人名字统计票数。用结构体数组把「姓名」与「得票数」绑在一起，每次输入后遍历比较姓名、命中则票数+1。这演示了结构体数组作为「小型数据库」的用法。
- **例9.8 建立简单链表（原书给出完整程序）**：定义 `struct Student{ int num; float score; struct Student *next; };`，用 `malloc` 分配 3 个结点，逐个填数据并 `p1->next=p2; p2->next=p3; p3->next=NULL;`，最后从 `head` 起遍历输出各结点数据。原书未在此例给出具体输出值，仅说明"要求输出各结点中的数据"。
- **例9.10 输出链表的函数 print（原书列出）**：把遍历过程封装成函数，体现「链表操作模块化」的写法。

## A2 — 何时触发

用户会在这些情境下：
- 有一组逻辑上属于同一实体的不同类型数据（学生、商品、员工档案），不知道怎么组织；
- 想排序/查找一批记录（按成绩排序学生、按姓名查人）；
- 数据量在运行期才确定、需要频繁插入删除，数组不合适；
- 编译报结构体相关的错（把类型当变量用、`->` 和 `.` 混用）；
- 想知道链表怎么建、怎么遍历、怎么插入删除。

语言信号：「结构体怎么定义」「struct 和 typedef struct 的区别」「`.` 和 `->` 什么时候用」「结构体数组怎么排序」「链表怎么建／遍历」「malloc 分配结点」「尾结点 next 为什么要置 NULL」「expected expression before 'struct'」。

**与相邻能力区分**：本能力管「复合数据类型的组织与动态结构」；如果问题是「指针本身怎么理解」→ 用 `pointer-model`；是「数组下标/长度」→ 用 `array-and-string`；是「数据要存到磁盘」→ 用本包内的《文件读写》能力卡。

## E — 执行步骤

**输入契约**：需要①要描述实体的成员清单及各成员的类型；②数据规模是否固定（决定用结构体数组还是链表）；③需要哪些操作（排序／查找／插入／删除／遍历输出）。成员清单不全时先补齐，否则结构体定义会漏字段。

**输出契约**：交付「结构体类型定义 → 变量/数组/结点定义 → 成员访问示例 → 若为链表则给出建表、遍历、释放的完整骨架」。

步骤：

1. **列成员清单**：逐条写出成员名与类型。完成标准：每个成员都能说清用途，无重复。
2. **定义类型**：`struct 名字 { 成员列表 };`。完成标准：编译通过，且未把类型当变量使用。
3. **选容器**（判停点）：规模固定 → 结构体数组（`struct Student s[100];`）；规模动态或需频繁增删 → 链表，转入 5。
4. **结构体数组路径**：定义数组 → 用 `.` 访问成员 → 排序时交换整个结构体（`t=s[i]; s[i]=s[j]; s[j]=t;`，同类型结构体可直接整体赋值）。完成标准：排序后成员的对应关系未错位。
5. **链表路径**：定义自引用结构 → 用 `malloc` 逐结点分配并检查返回值 → 填数据域 → 连接 `next` → **尾结点 `next=NULL`** → 遍历 `p=head;p!=NULL;p=p->next`。完成标准：遍历能在尾结点正常停止，不越界。
6. **资源释放**：链表用完要逐个 `free`，且必须先保存 `next` 再 `free` 当前结点。完成标准：无内存泄漏、无 free 后使用。
7. **验证**：空链表、单结点、多结点三种情形各测一次。完成标准：三种情形下遍历与输出均正确。

## B — 边界

- **不适用**：成员固定且规模很小（两三个字段、几个实例）时，用独立变量反而更简单，不必强上结构体。
- **作者盲点**（阶段 0 批判）：原书前言明确说明——链表内容"对非计算机专业学生来说，难度较大……只对链表作简单的介绍"，详细内容放在配套辅导书与习题中。因此本卡只覆盖单链表的建立与遍历；**双向链表、循环链表、有序插入、删除结点、逆转链表**等超出原书正文范围，需明确告知用户这是扩展内容。
- **易混淆**：①结构体**类型** vs 结构体**变量**（类型不占空间、不能赋值）；②`.` 用于变量、`->` 用于指针；③`typedef struct {...} Student;` 是把 `struct {...}` 起别名为 `Student`，不是定义了新类型；④共用体（`union`）的成员共享同一段内存，同一时刻只有一个成员有效，与结构体"成员各占空间"完全不同。
- **失败模式**：链表尾结点忘记置 `NULL`——遍历不终止，读到垃圾数据或崩溃；或 `free` 后继续用指针（悬垂指针）。
- **安全提示**：`malloc` 可能返回 `NULL`（分配失败），实战中必须检查；教学示例常省略此检查，不要照抄到生产代码。
