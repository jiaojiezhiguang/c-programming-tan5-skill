# 文件读写：打开—读写—关闭

## R — 原文

> "对文件读写之前应该'打开'该文件，在使用结束之后应'关闭'该文件。"
> ——第10章 §10.2 打开与关闭文件

> "如果不关闭文件就结束程序运行将会丢失数据。因为，在向文件写数据时，是先将数据输出到缓冲区，待缓冲区充满后才正式输出给文件。如果当数据未充满缓冲区时程序结束运行，就有可能使缓冲区中的数据丢失。"
> ——第10章 §10.2.2 用 fclose 函数关闭数据文件

> "所谓'文件'一般指存储在外部介质上数据的集合。"
> ——第10章 §10.1.1 什么是文件

## I — 自述

前面所有章节的程序，数据都在内存里，程序一结束就全没了。文件让数据能持久化到磁盘。C 把文件看成一串字符（或字节）的序列，按字符为单位存取，行的界限由程序自己控制，不受物理符号约束——这叫「流式文件」。

文件操作是一个固定的三步流程，任何一步做错都会出问题：

**①打开 `fopen(文件名, 方式)`。** 它返回一个指向该文件信息区的指针（`FILE *`）。注意这个指针**不是**指向磁盘上文件的开头，而是指向**内存中为该文件建立的信息区**的开头——理解这一点才不会把"文件指针"想错。方式决定能做什么：`r` 只读（文件必须已存在）、`w` 只写（已存在则先删除重建）、`a` 追加（写到末尾）、加 `+` 可读写；加 `b` 表示二进制方式（不做换行符转换）。**打开后必须检查是否返回 `NULL`**——`r` 方式打开不存在的文件、磁盘满、路径错都会返回 `NULL`，不检查就往下用会崩。

**②读写。** 按粒度分四种：字符（`fgetc`/`fputc`）、字符串（`fgets`/`fputs`）、格式化（`fscanf`/`fprintf`）、数据块二进制（`fread`/`fwrite`）。系统用一个隐式的**文件读写位置标记**记录当前读写到哪，每次读完自动后移。读完最后一个字符后再读，会得到 `EOF`（在 `stdio.h` 里定义为 -1）。检测是否读到末尾用 `feof(fp)`——注意它是在"读到文件尾之后"才为真，所以循环写法要和读取动作配合。

**③关闭 `fclose(fp)`。** 这一步最容易被当成可有可无，但它才是保证数据落盘的关键：写文件时数据先进入内存缓冲区（缓冲区满才真正写盘），如果不关闭就结束程序，缓冲区里没满的那部分数据就**丢了**。`fclose` 的动作正是"先把缓冲区数据刷到磁盘，再撤销文件信息区"。所以不是"建议关闭"，而是**必须关闭**。

再补一个易混点：文本文件 vs 二进制文件不是由读写函数决定的，而是由你想不想做换行符转换决定的。`fscanf`/`fprintf` 按 ASCII 方式读写，`fread`/`fwrite` 按二进制方式读写；`w` 与 `wb` 的区别只在于是否转换换行符（Windows 下 `\n` ↔ `\r\n`）。

## A1 — 书中案例

- **例10.2 复制文件（原书给出程序）**：以 `r` 打开 file1.dat、`w` 打开 file2.dat，`while(!feof(in)){ ch=fgetc(in); fputc(ch,out); }` 逐字符搬运，最后 `fclose` 两个文件。原书借此说明：①文件读写位置标记每读一个字节自动后移；②读到末尾后再读会得到 -1，`feof` 才转真；③若复制二进制文件，只需把 `"r"`、`"w"` 改成 `"rb"`、`"wb"`。
- **例10.5 两次访问同一文件（原书列出）**：要求第 1 次把内容显示到屏幕、第 2 次复制到另一文件。这演示了 `rewind` 或重新打开来复位文件读写位置标记的必要时机。
- **例10.1 从键盘输入存盘（原书给出运行结果）**：输入字符直到 `#` 结束，逐个 `fputc` 写入 file1.dat。原书特别说明 `fopen` 失败时输出 `cannot open file` 并 `exit(0)`，是"打开后必须判空"的标准示范。

## A2 — 何时触发

用户会在这些情境下：
- 程序算出的结果要存下来、下次运行要读回来；
- 要处理一个已有文件（读数据、统计、转换格式）；
- 写文件「成功」了，但打开一看末尾少了一截数据；
- 分不清文本方式和二进制方式该用哪个；
- `fopen` 返回空指针／提示打不开文件；
- 读文件时多读了一次、或多输出一行。

语言信号：「C 怎么读写文件」「fopen 失败／返回 NULL」「fclose 必须调用吗」「为什么文件里数据少了」「文本文件和二进制文件的区别」「feof 怎么用」「rewind」「fscanf 读文件」「EOF 是什么」「rb 和 r 的区别」。

**与相邻能力区分**：本能力管「持久化 IO」；如果问题是「字符串处理/数组」→ 用 `array-and-string`；是「指针指向文件信息区」的语义困惑 → 可参考 `pointer-model`；是「数据该用什么结构组织」→ 用本包内的《结构体与链表》能力卡。

## E — 执行步骤

**输入契约**：需要①文件路径与格式（文本／二进制）；②要做的操作（读／写／追加／复制／修改）；③数据项的字段与类型（决定用格式化读写还是数据块读写）。路径与格式不明时应先确认，不要默认文本方式。

**输出契约**：交付「打开代码（含判空）→ 读写循环 → 关闭代码」完整三段，并注明所选方式（r/w/a、是否加 b）的理由与失败处理。

步骤：

1. **定方式**：只读已有文件 → `r`；覆盖写 → `w`；追加 → `a`；需读写同一文件 → 加 `+`；不做换行转换 → 加 `b`。完成标准：能说出"用这个方式会/不会清空原文件"。
2. **打开并判空**：`if((fp=fopen(name,mode))==NULL){ /* 提示并退出 */ }`。完成标准：每个 `fopen` 后紧跟判空分支，无遗漏。
3. **读写循环**：按粒度选函数；用 `while(!feof(fp))` 或 `while((ch=fgetc(fp))!=EOF)` 控制；注意 `feof` 只有在"读过末尾之后"才为真。完成标准：循环能在末尾正确终止，不重复输出最后一项。
4. **关闭**（必做）：每个 `fopen` 对应一个 `fclose`，包括出错提前返回的路径。完成标准：所有出口都能保证文件被关闭。
5. **验证**：①写入后重新打开确认内容完整；②读出后与预期逐项比对；③测试文件不存在（`r` 方式）与空文件两种边界。完成标准：三种情形行为均符合预期。

## B — 边界

- **不适用**：数据只是程序运行期的中间结果、不需要跨次保留 → 用内存结构即可，不必上文件。
- **作者盲点**（阶段 0 批判）：本书基于 C89/C99，只讲标准 C 的文件 IO，**不涉及**现代替代方案（`open/read/write` 系统调用、`mmap`、CSV/JSON 库、数据库）。也不涉及并发写入、文件锁、崩溃一致性（fsync）。用户若在真实工程场景，应明确告知这些超出范围。
- **易混淆**：①「文件指针指向文件」是简化说法，实际指向内存中的文件信息区；②`EOF`（-1）是读取失败的返回值，不是文件里真存了一个 -1 的字节；③`feof` 的函数值（真=1/假=0）与 `EOF` 的假设值（-1）是两回事，原书专门提醒不要混淆；④`w` 方式会**清空**已存在的文件，误用会丢数据。
- **失败模式**：写完不 `fclose` → 缓冲区数据丢失（原书明确警告）；`fopen` 不判空 → 对 `NULL` 解引用导致崩溃。
- **安全提示**：拼接用户输入构造文件路径时存在路径穿越风险；不要照抄教学代码直接用于处理不可信路径的线上程序。
