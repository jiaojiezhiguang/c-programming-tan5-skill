# 控制结构选型与陷阱

## R — 原文

> "注意：无论 p 条件是否成立，只能执行 A 框或 B 框之一，不可能既执行 A 框又执行 B 框。"
> ——第2章 §2.5.3 三种基本结构（选择结构）

> "注意：while 循环的特点是先判断条件表达式，后执行循环体语句。"
> "注意：do…while 语句的特点是，先无条件地执行循环体，然后判断循环条件是否成立。"
> ——第5章 §5.2 / §5.3

> "注意：一般情况下，在执行一个 case 子句后，应当用 break 语句使流程跳出 switch 结构……"
> "case 标号只起标记的作用。……在执行完一个 case 标号后面的语句后，就从此标号开始执行下去，不再进行判断。"
> ——第4章 §4.7 说明(6)

> "在循环体中应有使循环趋向于结束的语句。……如果无此语句，则 i 的值始终不改变，循环永远不结束。"
> ——第5章 §5.2 例5.1 程序分析(3)

## I — 自述

控制结构只有三族，但每族内部有多个成员，选错或写错都会出问题。选型逻辑如下：

**选择：if 还是 switch？**
- 两个分支、或分支条件是「范围/复合条件」→ 用 `if`（`if…else if…else` 链适合多档但每档是范围判断的情形）；
- 多分支、且每一支对应一个**离散常量**（等级字符、菜单命令）→ 用 `switch`。它只做一次比较就跳到对应标号，比多层嵌套 if 清晰。
- 有一个特殊情况：如果 if 和 else 都是「给同一个变量赋值」，可以压缩成条件表达式 `(a>b)?a:b`（C 唯一的三目运算符）。

**循环：while / do…while / for？**
- 次数或结束条件在进入前就该判断、可能一次都不执行 → `while`（先判断后执行）；
- 至少要执行一次（比如先读一个数据再判断）→ `do…while`（先执行后判断）。注意二者只在「第一次条件就为假」时结果不同：此时 while 一次不做、do…while 做一次。
- 次数确定、有明确的「初值 / 条件 / 增量」三要素 → `for`。for 最灵活，能完全替代 while（`for(表达式1;表达式2;表达式3)` 等价于 `表达式1; while(表达式2){语句;表达式3;}`），也常用于「次数不确定但只需给结束条件」的情况。

**循环里要提前走：break 还是 continue？**
- `break`＝终止**整个**循环，跳到循环后面；
- `continue`＝只结束**本次**，接着判断下一次要不要继续。

写控制结构时，有几处是高频错误点，必须逐条自查：
1. 循环体有多条语句却漏了花括号——此时循环范围只到第一个分号；
2. 循环体内没有让条件终将变假的语句 → 死循环；
3. 累加器／循环变量没赋初值 → 值不可预测；
4. `switch` 的每个 case 末尾漏 `break` → 会一路穿透执行后面所有分支；
5. `if` 嵌套时 `else` 与「离它最近且尚未配对的 if」配对，与缩进无关 → 悬空 else；
6. 循环变量的边界差一位（配合数组时后果更严重）。

## A1 — 书中案例

- **例5.3 while 与 do…while 的比较（原书给出两次运行结果）**：同一个「求 i 到 10 的累加和」程序，输入 i≤10 时两者结果相同；输入 i=11 时，while 一次也不执行（sum 保持 0 初值），而 do…while 仍执行一次（sum=11）。原书结论："当 while 后面的表达式的第1次的值为'真'时，两种循环得到的结果相同；否则，二者结果不相同。"
- **例4.6 用 switch 划分成绩等级（原书给出运行结果）**：输入 'A' 输出 85～100。若各 case 后漏写 break，原书明确说"将连续输出 85～100 / 70～84 / 60～69 / <60 / enter data error!"——一次输入、五条输出。
- **例4.3 三数排序（原书给出结果）**：用三条 `if` + 三次交换实现由小到大输出，说明多档判断不一定需要 switch，范围比较用 if 更自然。

## A2 — 何时触发

用户会在这些情境下：
- 有多个分支要处理，纠结「if 嵌套还是 switch」；
- 循环要么一次不执行、要么至少执行一次，拿不准该用 while 还是 do…while；
- 程序卡死不结束，怀疑死循环；
- 输入一个值却输出了一大串结果（switch 穿透）；
- 循环次数对但累加结果不对（花括号／初值问题）；
- if 嵌套后分支走向和代码缩进显示的不一样。

语言信号：「if 和 switch 该用哪个」「while 和 do while 的区别」「程序死循环了」「为什么输入一个等级输出好几行」「switch 不加 break 会怎样」「else 到底配哪个 if」「循环只执行了第一条语句」「continue 和 break 区别」。

**与相邻能力区分**：本能力管「控制语句的正确写法与选型」；如果问题是「这个业务逻辑该怎么拆成步骤」→ 用 `algorithm-design`；是「数组下标差一位导致越界」→ 用 `array-and-string`。

## E — 执行步骤

**输入契约**：需要①要实现的判断／重复逻辑的文字描述；②数据范围与边界（尤其「可能一次都不发生」的情形）；③若是排错，需要出错代码片段或现象（不结束／多输出／少执行）。缺少代码时，只做选型建议并说明依据，不臆测具体 bug。

**输出契约**：交付「结构选型结论 + 理由 → 代码骨架 → 该结构的自查清单（哪几条需要特别检查）」。排错场景交付「现象 → 命中的错误模式 → 改前/改后代码」。

步骤：

1. **判定结构族**：这段逻辑是「二选一/多选一」（选择）还是「重复做」（循环）。完成标准：能说出选它的理由。
2. **选择族内选型**：分支条件是范围／复合 → `if` 链；是离散常量多分支 → `switch`；两支都是给同一变量赋值 → 考虑条件表达式。完成标准：选定并说明为什么另一选项不合适。
3. **循环族内选型**（判停点）：若「第一次条件就可能为假且此时不应执行」→ `while`；若「必须至少执行一次」→ `do…while`；若「次数确定或三要素清晰」→ `for`。选完进入 4。
4. **写骨架并做四项自查**：①多条语句是否加了 `{}`；②是否有推进循环变量／终止条件的语句；③循环变量与累加器是否赋了初值；④循环边界是否差一位（写成 `i<N` 而非 `i<=N`）。
5. **switch 专项自查**：每个 case 末尾是否有 `break`（最后一个 default 可省）；各 case 常量是否互不相同；是否需要利用「多个 case 共用一组语句」（此时故意不写 break）——若是故意穿透，必须在注释里写明。
6. **if 嵌套专项自查**：内层 if 是否都有 else（或加花括号明确范围）；`else` 的配对是否符合意图。
7. **验证**（判停点）：用至少两组数据验证，其中一组必须触发「条件一开始就不成立」的边界。若结果不符，回到 2 重新选型而不是在错的结构上打补丁。

## B — 边界

- **不适用**：如果用 `goto` 或 `break` 多层跳出更自然——本书不推荐无规律跳转，但真实代码里「多层循环一次性跳出」确实存在；此时应先考虑是否该把内层逻辑抽成函数用 `return` 提前返回，而不是堆标志变量。
- **作者盲点**（阶段 0 批判）：本书基于 C89/C99，未涉及 `switch` 的 `case` 作用域与变量声明限制、`for` 内声明变量的作用域陷阱（C99 才允许 `for(int i=…)`，且该变量出循环即失效）。用户若用现代编译器，这些细节需单独提醒。
- **易混淆**：①「判断框有两个出口」≠「选择结构有两个出口」；②`break` 在 `switch` 里是跳出 switch，在循环里是跳出循环，同一个词两种作用域；③`for(;;)` 三表达式全省略等于无条件循环，不是语法错误。
- **失败模式**：为了让代码短，把大量与循环控制无关的操作塞进 `for` 的三个表达式——原书明确提醒这"会使 for 语句显得杂乱，可读性降低，最好不要把与循环控制无关的内容放到 for 语句中"。
