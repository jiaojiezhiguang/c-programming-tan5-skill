# 数组与字符串处理批量数据

## R — 原文

> "（1）数组是一组有序数据的集合。……（2）用一个数组名（如 s）和下标（如15）来唯一地确定数组中的元素……（3）数组中的每一个元素都属于同一个数据类型。"
> ——第6章 章首

> "注意，下标是从0开始的，这10个元素是 a[0],a[1],…,a[9]。请特别注意，按上面的定义，不存在数组元素a[10]。"
> ——第6章 §6.1.2

> "起泡法的基本思路是：每次将相邻两个数比较，将小的调到前面。……如果有 n 个数，则要进行 n-1 趟比较。在第1趟比较中要进行 n-1 次两两比较，在第 j 趟比较中要进行 n-j 次两两比较。"
> ——第6章 §6.1.4 例6.3

> "C 语言规定了一个'字符串结束标志'，以字符'\0'作为结束标志。"
> ——第6章 §6.3.4

## I — 自述

当要处理的是「一批同类型数据」时，用 N 个独立变量是错的：一是定义几十个变量本身就很繁琐，二是这堆变量之间没有内在联系，无法用统一的方式遍历。数组解决的正是这个问题——给一批同类型数据起一个共同的名字，用下标区分彼此，从而可以配合循环批量处理。这是数组带来的最大收益：**数组 + 循环**，一套代码处理任意多个元素。

用数组有四件事必须刻在脑子里：

**第一，下标从 0 开始。** `int a[10];` 定义的是 10 个元素，它们是 `a[0]` 到 `a[9]`，**不存在 `a[10]`**。这是 C 语言最高频的错误来源，而且危险在于 C 不做下标越界检查（第1章 §1.3 特点(5)明确说"对数组下标越界不进行检查，由程序编写者自己保证程序的正确"）——越界不报错，只会悄悄改坏相邻内存，症状可能很久以后才出现。安全模板只有一个：定义长度 N，遍历一律 `for(i=0;i<N;i++)`。

**第二，长度必须是常量表达式。** `int a[n];`（n 是变量）在经典 C 里不合法——数组大小不能依赖运行期的变量值。要么用常量／符号常量，要么改用动态分配（malloc）。

**第三，初始化有默认规则。** 定义时给了长度并做了初始化，未被初始化列表覆盖的元素会自动置 0（字符数组置 `'\0'`，指针数组置 `NULL`）。想让整个数组全为 0，写 `int a[10]={0};` 就够，不必把 10 个 0 都写出来。

**第四，二维数组是「数组的数组」。** 定义时第一维可省、第二维不能省；逻辑上按行列理解（矩阵），但内存里是连续存放的。行数列数搞反是二维数组的典型错误。

**字符串则是「以 '\0' 结尾的字符数组」。** 这是 C 字符串的全部秘密：它没有单独的长度字段，靠结尾那个 `'\0'` 标记结束。所以字符数组存 n 个字符的字符串，至少要 n+1 个位置；用 `%s` 输出时，函数一直往后读直到遇见 `'\0'`，如果忘了放 `'\0'`，它就会继续读下去直到撞上内存里的某个 0——这就是"输出乱码一串"的成因。

**排序是数组最典型的应用**，也是「双重循环」的经典范式。起泡法的思路是：每一趟把当前未排好部分里的最大数"沉底"，共 n-1 趟；第 j 趟只需比较 n-j 次（已经沉底的不必再比）。所以外层管趟数、内层管本趟比较次数、内层上界随趟数递减——这个「内层上界依赖外层变量」的写法是双重循环的关键技巧，写错就变成多余比较或漏比较。

## A1 — 书中案例

- **例6.3 起泡法排序（原书给出完整程序与输出）**：`for(j=0;j<9;j++) for(i=0;i<9-j;i++) if(a[i]>a[i+1]){t=a[i];a[i]=a[i+1];a[i+1]=t;}`。原书分析指出：j=0 时内循环 i 从 0 到 8，比较 a[0]-a[1] 直到 a[8]-a[9]，完成第 1 趟；j=1 时内循环条件 `i<9-j` 相当于 `i<8`，只比较 8 次——已沉底的 a[9] 不再参与。原书同时说明排序还有选择法、希尔法等，习题要求用选择法再写一遍。
- **例6.2 用数组求 Fibonacci 数列（原书说明对比第5章）**：第5章用简单变量只能「算一个丢一个」，无法直接输出第 25 个数；改用 `f[40]` 保存每一项后，`f[i]=f[i-2]+f[i-1]` 递推填充，需要哪一项直接取下标即可。这个对比清楚说明了"用数组保留历史结果"的价值。
- **例6.1 逆序输出（原书给出输出）**：`int a[10]` 依次赋值 0~9，再按下标从大到小输出。原书在此处专门列出了"常见的错误"——把循环写成 `for(i=1;i<=10;i++)`，同时犯了「从 1 开始」和「写 a[10] 越界」两个错。

## A2 — 何时触发

用户会在这些情境下：
- 要处理几十上百个同类型数据（成绩、数列、矩阵），不知道该怎么存；
- 程序出现「下标越界」类问题：某个变量莫名被改、偶发崩溃、结果差一位；
- 想把一段重复处理改写成数组 + 循环；
- 要排序、查找、求最大最小值、做矩阵运算；
- 字符串处理出问题：输出一串乱码、字符串比较结果不对、字符数组长度不够；
- 二维数组行列搞混、传参时不知道第二维能不能省。

语言信号：「怎么存一批数据」「数组下标越界」「a[10] 到底有几个元素」「冒泡排序怎么写」「双重循环内层条件怎么写」「字符串为什么输出乱码」「'\0' 是什么」「char s[10] 能存几个字符」「strcmp 比较出来是乱的」「二维数组怎么传参」。

**与相邻能力区分**：本能力管「一批数据怎么存、怎么按某种次序处理」——凡是围绕具体数据集合的问题（存、遍历、排序、查找、统计、字符串）都归这里，**包括排序算法的写法与边界条件**。若问题只是脱离具体数据的纯循环语法（死循环、break/continue、for 三表达式）→ 用 `control-flow`；是「数组名作函数参数为什么会改掉原数组」→ 用 `function-and-recursion`；是「用指针遍历数组的原理」→ 用 `pointer-model`。

## E — 执行步骤

**输入契约**：需要①要处理的数据类型与规模（元素个数是否固定、上限多少）；②是几维（一维序列／二维表／字符串）；③要做的操作（遍历／排序／查找／统计／矩阵运算）。规模不定时必须先问清上限，因为数组长度要在编译期确定。

**输出契约**：交付「数组定义（含长度依据）→ 初始化方式 → 遍历/处理循环（下标范围写明）→ 边界处理说明」。字符串场景额外交付「容量是否含 `'\0'`」的判断。

步骤：

1. **定维数与长度**：一维序列用一维、表/矩阵用二维、文本用字符数组。长度取常量或符号常量，并核对是否为「最大可能元素数」。完成标准：长度来源可一句话说清（如 `#define N 100`）。
2. **写下标范围**（关键一步）：一维遍历写 `for(i=0;i<N;i++)`；二维写双层 `for(i=0;i<行;i++) for(j=0;j<列;j++)`。完成标准：范围内每个下标都 < 定义长度，且覆盖第 0 个元素。
3. **决定初始化方式**：需要全 0 用 `={0}`；需要指定初值用初始化列表；需要运行期赋值就写赋值循环。完成标准：不存在「依赖未初始化元素的值」的语句。
4. **写处理逻辑**：排序用双重循环（内层上界随外层递减）；查找用循环 + 命中即 `break`；统计用「遍历 + 条件累加」。完成标准：处理逻辑只遍历一次或明确说明的固定次数。
5. **字符串专项**（判停点）：若涉及字符串，检查 ①容量是否 ≥ 字符数+1；②是否确实写入了 `'\0'`；③用 `%s` 输出前是否保证有结束标志。任一项不满足 → 先修容量/结束标志再继续。
6. **边界验证**：用「空/单元素」「刚好满长度」「含重复值」三类数据各测一次。完成标准：三类数据下输出均正确，且无越界（可用编译器的越界检查开关辅助验证）。

## B — 边界

- **不适用**：数据量在运行期才确定且可能很大时，定长数组不合适——应改用动态内存分配（`malloc`/`free`，见第8章 §8.8），此时本能力的「常量长度」前提不成立。
- **作者盲点**（阶段 0 批判）：本书基于 C89/C99 之前的环境，明确说 `int a[n];` 不合法；C99 起引入了变长数组（VLA），现代 GCC/Clang 默认支持。回答时必须说明「按本书标准不合法，但现代 C99+ 允许」，不能一刀切说错。
- **易混淆**：①「数组定义时的 `a[10]`」是长度，与「引用时的 `a[6]`」是元素，形式相同含义不同；②「数组有序」指有下标次序，不是「已排序」；③字符数组 `char s[10]` 存 9 个字符的字符串是满的，存 10 个字符就需要 11 个位置。
- **失败模式**：把「逆序输出」和「逆序存放」混为一谈——前者只改变输出顺序，原数组不变；后者才真的交换元素。
- **相邻陷阱**：数组名作函数实参时，传的是首元素地址而非整个数组的副本，因此函数内改动会影响原数组——这一点常被误当成「值传递」（详见 `function-and-recursion`）。
