## 这是什么

一本 400 页的 C 语言教材，读完能懂，但遇到具体问题还是不知道该往哪一章翻。

这个项目做了三件事：

1. **蒸馏** — 把书里的方法论结构提炼成 10 个「能力单元」，每个单元包含：原文引用（带章节）、别人的话重述、书中案例、触发场景、可执行步骤、边界
2. **验证** — 用 117 条测试用例验证这些能力卡能不能被正确找到，含三轮不同可信度的验证
3. **打包** — 编译成可直接导入 AI 助手的技能包，两种形态（7 入口 / 1 入口）

## 十张能力卡

| 能力 | 解决什么 | 重要度 |
|---|---|---|
| `program-skeleton` | 程序骨架、编译连接四步、语法错/逻辑错/运行时错三类分诊 | critical |
| `algorithm-design` | 六阶段设计流程、自顶向下细化、模块划分、流程图选型 | critical |
| `control-flow` | if/switch、while/do-while/for 选型、6 类高频陷阱 | high |
| `array-and-string` | 下标 0 基、越界、起泡排序、`'\0'` 与字符串 | high |
| `function-and-recursion` | 参数传递单向性、定义 vs 声明、递归两要素 | critical |
| `pointer-model` | 地址模型、带类型的地址、指针三概念、野指针三态 | critical |
| `struct-and-linked-list` | 结构体类型 vs 变量、自引用结构、链表 | medium |
| `file-io` | 打开判空—读写—必须关闭、缓冲区语义 | high |
| `debug-and-test` | 调试 vs 测试、四类测试数据设计 | high |
| `glossary` | 75 条术语，重点辨析易混概念 | medium |

每张卡都不是摘要，而是「**什么时候用、怎么用、什么时候不该用**」的完整契约。

举一个例子——`pointer-model` 的 E 段（执行步骤）长这样：

```
1. 分离两层：先确认用户卡在「地址这一层」还是「类型这一层」
2. 建立地址模型：用房间号比喻讲清直接访问 vs 间接访问
3. 区分三个概念：指针（地址，是值）/ 指针变量（存地址的变量）/ 基类型（指向什么）
4. 说清 * 的两义（判停点）：定义语句里的 * 是标记，表达式里的 * 是解引用
   → 用户混淆这两处就回到第 3 步，不往下走
5. 检查基类型匹配
6. 安全检查（必做）：每个被解引用的指针要么已指向合法对象，要么显式置 NULL
7. 给出可运行对照：用「交换指向 vs 交换值」演示 p 与 *p 的差别
```

## 快速开始

### 用技能包

```bash
cd skillpack
chmod +x scripts/*.sh

# 装到项目专用目录（推荐，不影响全局技能列表）
./scripts/install.sh --pack --project "/你的/工作目录"

# 或装到用户级
./scripts/install.sh --pack --user
```

装完**新开一个会话**生效。然后正常提问即可：

| 你这样问 | 走哪张卡 |
|---|---|
| 写个最简单的 C 程序 / 编译报错 `expected ';'` | `program-skeleton` |
| 这题不知道从哪下手 / 主函数三百行了怎么拆 | `algorithm-design` |
| if 还是 switch / 为什么死循环了 | `control-flow` |
| 怎么存 50 个成绩 / 冒泡排序 / 字符串乱码 | `array-and-string` |
| 函数里改了变量外面没变 / 递归怎么停 | `function-and-recursion` |
| 指针到底是什么 / `*p` 和 `&a` / 野指针崩了 | `pointer-model` |
| 结构体、文件读写、怎么测、术语区别 | 路由入口转对应卡 |

详见 [skillpack/INSTALL.md](skillpack/INSTALL.md)。

## 技术方法

用的是 [cangjie-skill](https://github.com/) 五阶段流水线：

```
阶段 0  整书理解 ──────────→ BOOK_OVERVIEW.md（骨架 + 8 个读者任务 + 作者局限）
阶段 1  五路并行提取 ──────→ 63 条候选（每条带原文锚点）
阶段 1.5 三重验证 ────────→ 63/63 锚点机械核验通过
阶段 1.6 晋级门 ──────────→ 6 独立 Skill + 4 路由卡
阶段 2  RIA++ 能力卡 ─────→ 10 张（六段结构）
阶段 3  Zettelkasten ────→ also_read 关系网 + 术语表
阶段 4  压力测试 ─────────→ 117 条用例（三轮不同可信度）
阶段 5  编译与交付 ───────→ 两种形态 + 3 个脚本 + 5 份文档
```

完整的候选池、能力卡源文件、评测用例都在 [pipeline/](pipeline/)，可复现、可审计。

### 三个关键技术细节

**① 文字源要先验文字层**
拿到的 4 个来源（1 个 137MB md + 3 个 PDF）全是扫描图，PDF 文字层检测为 0。最后靠自己找的带文字层 DOCX（5.3MB）解决——8,344 段 / 387,782 字，零识别误差。

**② 原文锚点要机械核验，不能靠人眼**
63 条候选逐条写出「原句片段」，用脚本规范化（去空白）后比对全文，全部命中。这个步骤抓出了我 4 处转写错误（`%lf` 被 OCR 成 `%1f`、`filel` vs `file1` 等）。

**③ 评测的"未见数据"必须真的未见**
这是本项目最值得说的教训：

| 轮次 | 题目来源 | 结果 | 可信吗 |
|---|---|---|---|
| 一 | 自己写 71 条 | F1 = 1.000 | ❌ 自证 |
| 二 | 自己换措辞 39 条 | 87% | ⚠️ 测出 2 个真缺陷 |
| 三 | **第三方 agent 独立出题 20 条** | 91.7% | ✅ |

作者出题会不自觉匹配自己的描述。只有让不知道你写了什么的人出题，才叫验证。

## 已知边界

这套东西**明确不覆盖**（每张卡里都写了）：

- 现代工程实践：Makefile/CMake、版本控制、单元测试框架、sanitizer、静态分析
- C11/C17/C23 新特性（`_Generic`、线程、原子操作）
- C++ 及其他语言
- 并发、网络、图形界面、数据库

问了它会告诉你超范围，不会硬编答案。

另外教材基于 **C99 / Visual C++ 6.0 时代**。用现代编译器（GCC 13+、Clang）时部分老示例会触发新警告——卡片的 B 段会提示差异。

## 关于这个项目

作者是**西安交通大学**的大一学生。

做这个项目的起因很朴素：学 C 语言时发现，书读得懂，但真遇到 bug 还是不知道该往哪一章翻。所以想试试能不能把教材变成「能用起来的东西」——不是又一个笔记，而是能回答问题、知道边界、说清步骤的工具。

过程中最大的收获不是那 10 张卡，而是明白了**怎么诚实地评估自己做的的东西**：

- 自己出题自己测出来的 100% 毫无意义
- 让第三方出题后的 91.7%，和「输出质量打平」这个反向发现，虽然不好看，但有用
- 明确写下「未做的验证」，比模糊地说「完成了」更有价值

如果这个项目对你有帮助，或者你发现了问题，欢迎提 issue。
