## ⚠️ 为什么没有原书全文

原始工作目录里有一个 `_book_text.md`（804 KB），是从正版电子书中抽取的**全文文字**。

**它被有意排除在本仓库之外**，原因有两个：

1. **版权**：全文属谭浩强与清华大学出版社的著作权，公开上传不构成合理使用
2. **不必要**：本项目的产物是「方法论结构」，不是原文复制

本仓库保留的是**短引用**——每张能力卡的 R 段引用原文不超过 150 字并标注章节，全项目引用合计约 2,400 字（占原书 0.6%），属合理引用范围。

### 如果你想复现

需要自备正版电子书（纸质书扫描亦可），用以下方式得到文字源：

```python
# 带文字层的 PDF
import pymupdf
doc = pymupdf.open("book.pdf")
text = "\n".join(p.get_text() for p in doc)

# 带文字层的 DOCX
from docx import Document
text = "\n".join(p.text for p in Document("book.docx").paragraphs if p.text.strip())
```

得到文字后存为 `_book_text.md`，即可按 `candidates/` 里的锚点逐条核对。

### 判断电子书有没有文字层

```python
import pymupdf
doc = pymupdf.open("book.pdf")
print("首 10 页文字长度:", sum(len(doc[i].get_text()) for i in range(min(10, doc.page_count))))
# 接近 0 → 纯扫描版，需要 OCR（慢且对代码识别不准）
```

**这次的经验**：拿到的 4 个来源（1 个 137MB md + 3 个 PDF）全是扫描图，最后是靠自己找的带文字层 DOCX 才解决问题。**先测文字层，再决定 OCR，不要凭文件大小猜**。

## 蒸馏方法

用的是 [cangjie-skill](https://github.com/) 的五阶段流水线：

| 阶段 | 做了什么 | 产出 |
|---|---|---|
| 0 | 整书理解 | `BOOK_OVERVIEW.md`（骨架 + 8 个读者任务 + 作者局限） |
| 1 | 五路并行提取候选 | `candidates/*.md`（63 条，每条带原文锚点） |
| 1.5 | 三重验证（原文锚定/边界/价值） | **63 条锚点全部机械核验通过** |
| 1.6 | 晋级门（五条判据） | 6 promoted + 4 router |
| 2 | RIA++ 能力卡 | `cards/*.md`（10 张） |
| 3 | Zettelkasten 链接 | `also_read` 关系 + GLOSSARY |
| 4 | 压力测试 | `evals/`（117 条用例，含三轮验证） |
| 5 | 编译与交付 | `skillpack/`（pack 7 入口 / single 1 入口） |

## 评测方法（这部分比结果更值得看）

### 三轮验证，三个不同可信度的数字

| 轮次 | 数据集 | 最优命中 | 性质 |
|---|---|---|---|
| 一 | 71 条，**自己出题** | F1 = 1.000 | ❌ 过拟合，不可引用 |
| 二 | 39 条 holdout，仍是自己换措辞 | 87% → 93.8% | ⚠️ 暴露 2 个真缺陷 |
| 三 | 20 条，**第三方 agent 独立出题** | **91.7%** | ✅ 最可信 |

第三轮之前，我发现了一个机制性问题：**题目和描述都是同一个作者写的**，作者会不自觉写出「刚好匹配自己描述」的题，于是必然收敛到 100%。这是自证，不是验证。

解法：让一个**没见过任何 skill 描述**的 agent 扮演大一学生，写出 20 条真实困惑（10 条明确 / 6 条模糊跨主题 / 4 条该超范围），我事后标注答案，跑 3 次采样。

结果：最优 91.7%、最终可达 100%、逐题稳定 18/20。

那 2 条波动的题（`Segmentation fault 怎么查`、`跑十次偶尔出错`）横跨 `pointer-model` / `program-skeleton` / `debug-and-test`，真人问也不会有唯一答案——是真实语义灰区，不是 bug。

**结论**：`F1 = 1.000` 那个数字请不要引用。真实成绩是 91.7% / 100%。

### 输出质量：诚实地说，打平

| 测试 | 带技能 | 不带技能 |
|---|---|---|
| 机械断言（29 条，6 个任务） | 6/6 | 6/6 |
| 匿名 A/B 语义盲评（6 组） | 3 胜 | 3 胜 |

**技能包不会让 AI 把单道题答得更好。** 一个能力足够的通用模型，不带这套东西也能写出同样正确的 C 代码。

那它的价值在哪？

1. **可发现性** — 不知道该怎么问时，给出结构化入口
2. **方法一致性** — 同一套「先算法 → 再结构 → 再边界」的流程，而非临场发挥
3. **边界自觉** — 每张卡强制声明「本书不适用什么」，避免把教学代码当工程方案

这个反向发现在 `docs/EVALUATION.md` 里完整记录，包括我自己 1 处标注错误的承认。
