# 原则候选（principle）

- id: p01
  title: 程序 = 算法 + 数据结构
  type: principle
  source_chapter: 第2章 §2.1 程序=算法+数据结构
  source_quote: |
    "著名计算机科学家沃思(Niklaus Wirth)提出一个公式：算法+数据结构=程序。直到今天，这个公式对于过程化程序来说依然是适用的。"
  summary: |
    一个程序只有两部分信息：对数据的描述（数据结构）和对操作的描述（算法）。
    数据是操作的对象，操作的目的就是加工数据得到结果。
    作者补充：完整地说，一个程序设计人员要同时具备算法、数据结构、程序设计方法、语言工具四方面知识；
    其中「算法是灵魂，数据结构是加工对象，语言是工具，编程需要采用合适的方法」。
  tags: [principle, foundation, algorithm, data-structure]

- id: p02
  title: 先算法后编码（不要坐下来就写程序）
  type: principle
  source_chapter: 前言「怎样学习C程序设计」/ 第2章 §2.6
  source_quote: |
    "在各例题中，在提出问题后，都先进行分析问题，讨论解题思路，也就是构造算法，然后才是根据算法编写程序，而不是先列出程序再解释程序……引导读者在处理任务时先考虑算法再编程，而不是坐下来就写程序，养成良好的编程习惯。"
  summary: |
    面对任务，先把算法（做什么、怎么做、分几步）想清楚并写出来，再动手编码。
    编码只是「把已细化的算法用计算机语言表示」。
    反模式：先敲出一堆代码，再回头解释它在干什么。
  tags: [principle, algorithm-first, habit]

- id: p03
  title: 结构化算法必须单入口、单出口、每部分可达
  type: principle
  source_chapter: 第2章 §2.5.3 三种基本结构
  source_quote: |
    "以上3种基本结构，有以下共同特点：(1)只有一个入口……(2)只有一个出口……(3)结构内的每一部分都有机会被执行到。也就是说，对每一个框来说，都应当有一条从入口到出口的路径通过它。"
  summary: |
    判定一个算法/程序片段是否「结构化」的三条硬性检查：
    ①单入口；②单出口；③结构内每个部分都存在一条从入口到出口的通路（没有永远执行不到的「死块」）。
    不满足就说明存在无规律跳转，需要改造（引入标志变量收敛出口）。
    附注：判断框本身有两个出口，但选择结构整体只有一个出口，不要混淆。
  tags: [principle, checklist, structured-programming]

- id: p04
  title: 变量必须先定义、后使用
  type: principle
  source_chapter: 第3章 §3.2.1 常量和变量
  source_quote: |
    "变量必须先定义，后使用。在定义时指定该变量的名字和类型。"
  summary: |
    使用变量前必须定义（指定名字和类型），编译系统据此分配存储单元、建立变量名与地址的对应表。
    变量名本质是「一个名字代表的存储地址」，取值时按名字找到地址再从该单元读取。
    推论：C 语言里没有「未声明就可用」的变量；类型也必须在定义时明确。
  tags: [principle, declaration, rules]

- id: p05
  title: 循环体内必须有使循环趋于结束的语句
  type: principle
  source_chapter: 第5章 §5.2 用 while 语句实现循环（例5.1程序分析）
  source_quote: |
    "在循环体中应有使循环趋向于结束的语句。例如，在本例中循环结束的条件是'i>100'，因此在循环体中应该有使i增值以最终导致i>100的语句……如果无此语句，则i的值始终不改变，循环永远不结束。"
  summary: |
    任何循环都必须存在一个能让循环条件最终变为假的机制，通常写在循环体内（i++ 之类）。
    缺了它，循环条件永远为真＝死循环。
    推论：写循环时，除了写循环条件，还要能指出「哪一句让这个条件终将不成立」。
  tags: [principle, loop, termination, rule]

- id: p06
  title: 数组下标从 0 开始，a[n] 的合法下标是 0..n-1
  type: principle
  source_chapter: 第6章 §6.1.2 怎样引用一维数组元素
  source_quote: |
    "注意，下标是从0开始的，这10个元素是 a[0],a[1],…,a[9]。请特别注意，按上面的定义，不存在数组元素a[10]。"
    "数组元素的下标从0开始，如果用'int a[10];'定义数组，则最大下标值为9，不存在数组元素a[10]。"
  summary: |
    int a[10] 表示「10 个元素」，下标范围是 0～9，a[10] 越界不存在。
    这是 C 语言最高频的 off-by-one 错误来源：循环写成 i=1;i<=10 就同时犯了「从1开始」和「越界」两个错。
    推论：定义长度 N、遍历写 for(i=0;i<N;i++) 是唯一安全的模板。
  tags: [principle, array, off-by-one, rule]

- id: p07
  title: 指针就是地址
  type: principle
  source_chapter: 第8章 §8.1 / §8.9 有关指针的小结
  source_quote: |
    "作者明确指出'指针就是地址'。很多读者反映，这是画龙点睛，把指针讲透了，抓住了问题的本质。有了这个明确的认识，很多不清楚的问题都迎刃而解了。"
  summary: |
    作者全书最核心的一句断言：指针＝地址（形象说法，物理实现是地址）。
    由此可直接推出：
    · &a 是变量 a 的地址，也就是 a 的指针；
    · 指针变量是存放地址的变量，它的值是一个地址（一个指针）；
    · 数组名是数组首元素的地址（指针），函数名是函数代码区首字节的地址。
    但必须同时记住：C 的地址是「带类型的地址」，含位置 + 类型两层信息，所以指针要指定基类型。
  tags: [principle, pointer, core-claim]

- id: p08
  title: 引用指针变量前必须先赋值
  type: principle
  source_chapter: 第8章 §8.9 有关指针的小结
  source_quote: |
    "应注意，p 的值为NULL与未对 p 赋值是两个不同的概念。前者是有值的（值为0），不指向任何变量，后者虽未对 p 赋值但并不等于 p 无值，只是它的值是一个无法预料的值，也就是 p 可能指向一个事先未指定的单元。这种情况是很危险的。因此，在引用指针变量之前应对它赋值。"
  summary: |
    指针变量定义后若不赋值，它的值是「无法预料的」，可能指向任何地方——此时解引用或写入会破坏无关内存。
    必须区分三态：①未赋值（野值，危险）；②赋为 NULL（值为0，明确不指向任何对象，可判断）；③指向有效对象。
    规则：使用 *p 或写 *p 之前，先确保 p 已指向一个合法单元；需要「空指针」语义时显式赋 NULL。
  tags: [principle, pointer, initialization, safety]

- id: p09
  title: 实参向形参是单向值传递
  type: principle
  source_chapter: 第7章 §7.3.3 函数调用的过程
  source_quote: |
    "实参向形参的数据传递是'值传递'，单向传递，只能由实参传给形参，而不能由形参传给实参。实参和形参在内存中占有不同的存储单元，实参无法得到形参的值。"
  summary: |
    函数调用时只把实参的值复制给形参，二者占不同存储单元，形参在函数内的改变不影响实参。
    因此「在函数里改形参」无法把结果带回调用者。
    要带回多个结果或修改实参指向的对象，必须传指针（地址），通过 *p 修改目标。
  tags: [principle, function, pass-by-value, parameter]

- id: p10
  title: 函数就是功能，函数名应见名知义
  type: principle
  source_chapter: 第7章 §7.1 为什么要用函数
  source_quote: |
    "注意：函数就是功能。每一个函数用来实现一个特定的功能。函数的名字应反映其代表的功能。"
  summary: |
    把「函数」理解为「一段有名字的功能」，比抽象定义更好用：
    每个函数只实现一个特定功能，函数名要直接反映它做什么（max、swap、print_star）。
    推论：设计程序时按功能划分模块，一个模块对应一或多个函数；函数名起得准，调用处就读得懂。
  tags: [principle, function, naming, modularity]

- id: p11
  title: 用符号常量做到「见名知义、一改全改」
  type: principle
  source_chapter: 第3章 §3.2.1 常量和变量（符号常量）
  source_quote: |
    "①含义清楚。看程序时从 PI 就可大致知道它代表圆周率。在定义符号常量名时应考虑'见名知义'。……②在需要改变程序中多处用到的同一个常量时，能做到'一改全改'。"
  summary: |
    不要把魔法数字散落在代码里，而用 #define 定义有意义的符号常量（PI、PRICE、SUM）。
    好处两条：①读代码时名字自解释；②数值要调整时只改定义处一处，不会漏改。
    注意：符号常量在预编译阶段被文本替换，不占存储单元，不能对它赋新值；习惯上用大写与变量区分。
  tags: [principle, magic-number, macro, maintainability]

- id: p12
  title: 初学不要过早使用易错的语言细节
  type: principle
  source_chapter: 前言「怎样学习C程序设计」第2条
  source_quote: |
    "初学时，不宜过早地使用C语言的某些容易引起错误的细节（如不适当地使用++和--）。"
  summary: |
    学习阶段的重点是解题思路与算法，不是炫语法技巧。
    像 ++/-- 的副作用、复杂逗号表达式、把大量操作塞进 for 的三个表达式这类「能写但难读」的写法，初学阶段应回避。

  tags: [principle, learning, readability, style]

- id: p13
  title: 程序应当包含注释
  type: principle
  source_chapter: 第1章 §1.4.2 C 语言程序的结构（第8条）
  source_quote: |
    "程序应当包含注释。一个好的、有使用价值的源程序都应当加上必要的注释，以增加程序的可读性。"
  summary: |
    注释不参与编译、不产生目标代码，只给人看，但它是「有使用价值的程序」的必要组成。
    目的是让自己和别人能看懂各部分在做什么。
    C 提供两种注释：// 单行注释（到行尾）与 /* */ 块注释（可跨行）；字符串里的 // 和 /* 不算注释。
  tags: [principle, comment, readability]

- id: p14
  title: 用完文件必须关闭，否则可能丢数据
  type: principle
  source_chapter: 第10章 §10.2.2 用 fclose 函数关闭数据文件
  source_quote: |
    "如果不关闭文件就结束程序运行将会丢失数据。因为，在向文件写数据时，是先将数据输出到缓冲区，待缓冲区充满后才正式输出给文件。如果当数据未充满缓冲区时程序结束运行，就有可能使缓冲区中的数据丢失。"
  summary: |
    写文件是「先写缓冲区、满了才落盘」，所以程序结束前不 fclose 就可能丢最后一批数据。
    fclose 的作用正是「先把缓冲区数据刷到磁盘，再撤销文件信息区」。
    规则：打开的文件在程序终止前都要关闭；这是流程的强制收尾，不是可选项。
  tags: [principle, file-io, resource-management, data-loss]

- id: p15
  title: 模块宜小、耦合宜少
  type: principle
  source_chapter: 第2章 §2.6 结构化程序设计方法
  source_quote: |
    "程序中的子模块一般不超过50行，即把它打印输出时不超过一页，这样的规模便于组织，也便于阅读。划分子模块时应注意模块的独立性，即使用一个模块完成一项功能，耦合性愈少愈好。"
  summary: |
    划分子模块的两条量化约束：
    ①单个模块不超过约 50 行（打印不超过一页）——便于组织与阅读；
    ②模块间耦合越少越好，一个模块只完成一项功能——便于独立修改与复用。
    本质是「分而治之」：把大任务切成相对简单的小任务。
  tags: [principle, modularity, coupling, size-limit]

- id: p16
  title: 全局变量尽量少用
  type: principle
  source_chapter: 第7章 §7.8 局部变量和全局变量
  source_quote: |
    "全局变量过多，会降低程序的清晰性，人们往往难以清楚地判断出每个瞬时各个外部变量的值。"
    "全局变量的作用域应十分慎重，因为在执行一个文件中的操作时，可能会改变该全局变量的值，会影响到另一文件中全局变量的值，从而影响该文件中函数的执行结果。"
  summary: |
    全局变量在整个程序运行期一直占用存储单元，且任何函数都能改它，导致：
    ①清晰性下降——难以判断某一时刻各外部变量的值；②可靠性低——一处出错牵连全局；
    ③通用性差——函数依赖外部状态，跨文件时更易互相影响。
    规则：能用局部变量解决就不用全局变量；必须共享时才用全局，并清楚它的作用域边界。
  tags: [principle, scope, global-variable, reliability]

- id: p17
  title: 输入输出是「函数化」的，用 scanf/printf 并注意格式符匹配
  type: principle
  source_chapter: 第1章 §1.4.2（第7条）/ 第4章 例4.1程序分析
  source_quote: |
    "C 语言本身不提供输入输出语句。输入和输出的操作是由库函数 scanf 和 printf 等函数来完成的。"
    "在用 scanf 函数输入双精度实型数据时，不能用'%f'格式声明，而应当用'%lf'格式声明。"
  summary: |
    C 没有内建 IO 语句，IO 全靠库函数（需 #include <stdio.h>）。
    因此格式符必须与数据类型严格匹配：
    · double 输入用 %lf（用 %f 会出错），输出可用 %f/%lf/%m.nf；
    · int 用 %d，float 用 %f，char 用 %c，字符串用 %s。
    推论：格式符错配是最隐蔽的「能编译、结果错」类 bug 之一。
  tags: [principle, io, format-specifier, scanf]
