# 术语候选（glossary）

> 提取自《C程序设计（第五版）》谭浩强著，文字源 `_book_text.md`。
> 提取器：glossary-extractor。只收作者明确定义或特别强调的技术概念。

| 术语 | 作者的定义 / 用法 | 出处 | 和常识用法的差异 |
|---|---|---|---|
| 程序 | 一组计算机能识别和执行的指令；每一条指令使计算机执行特定操作 | §1.1 | 不是「软件」的同义词；程序＝指令序列，软件＝程序＋文档（§1.6） |
| 计算机语言 | 计算机和人之间都能识别的语言；分机器语言、符号语言、高级语言三个发展阶段 | §1.2 | 强调「能被双方识别」，故高级语言必须经编译/解释才能执行 |
| 机器语言 | 计算机能直接识别和接受的二进制代码（机器指令）的集合 | §1.2 | 是唯一无需翻译即可执行的形态 |
| 符号语言（汇编语言） | 用英文字母和数字表示指令的语言，需经汇编程序转换为机器指令 | §1.2 | 仍属「低级语言」，依赖具体机器 |
| 高级语言 | 不依赖具体机器、接近自然语言与数学语言的编程语言 | §1.2 | 又细分为非结构化 / 结构化 / 面向对象三代 |
| 源程序 | 用高级语言写的程序 | §1.5 | 与「目标程序」相对；后缀通常为 .c |
| 目标程序 | 源程序经编译后得到的二进制目标文件（如 .obj） | §1.5 / §1.2 | 还不能直接运行，必须再经连接 |
| 可执行程序 | 目标模块与函数库连接装配后生成的、可供计算机执行的程序（如 .exe） | §1.5 | 编译≠连接，两步不能省 |
| 编译预处理 | 编译前由预处理器处理 #include、#define 等指令的过程 | §1.4.2 | 发生在正式编译之前，是独立的阶段 |
| 注释 | 从 // 到行尾、或 /* 到 */ 的内容；预编译时被替换为一个空格，不产生目标代码 | §1.4.1 / §1.4.2 | 只是给人看的，对运行无作用；字符串里的 // 和 /* 不算注释 |
| 算法 | 为解决一个问题而采取的方法和步骤；广义上不限于计算问题 | §2.2 | 不只是「数学公式」；乐谱、菜谱都是算法 |
| 计算机算法 | 计算机能执行的算法，分数值运算算法与非数值运算算法两类 | §2.2 | 区别于「人能做但计算机做不到」的步骤（如「替我理发」） |
| 算法的特性 | 有穷性、确定性、有零个或多个输入、有一个或多个输出、有效性 | §2.4 | 五条是「有效算法」的判定清单，缺一不可 |
| 有穷性 | 算法应包含有限的操作步骤，而不能是无限的 | §2.4 | 注意是「步骤有限」，不是「时间短」 |
| 确定性 | 算法每一步都应当确定，不应含糊、模棱两可、有歧义 | §2.4 | 与「精确到小数位」无关，指含义唯一 |
| 有效性 | 算法中每一步都应能有效执行并得到确定结果 | §2.4 | 如 b=0 时 a/b 就不能有效执行 |
| 流程图 | 用图框表示各种操作的算法表示法；含起止框、输入输出框、判断框、处理框、流程线、连接点、注释框 | §2.5.2 | 判断框有**两个**出口，是它最易被误解之处 |
| BS 型算法 | 流程可随意跳转、如同「一碗面条」般毫无头绪的算法 | §2.5.3 | 是反面典型；结构化就是要消除它 |
| N-S 流程图（盒图） | 完全去掉流程线、全部算法写在一个矩形框内的结构化流程图 | §2.5.4 | 上下顺序即执行顺序，天然结构化，不可能出现无规律跳转 |
| 伪代码 | 介于自然语言与计算机语言之间的算法描述工具，无固定语法 | §2.5.5 | 书写/修改方便，适合设计期；但不如流程图直观、易出逻辑错 |
| 结构化算法 | 由三种基本结构顺序组成的算法；基本结构之间不存在向前或向后的跳转 | §2.5.4 | 判据是「能否分解为基本结构」，不是「代码短不短」 |
| 三种基本结构 | 顺序结构、选择结构、循环结构 | §2.5.3 | 共同特点：单入口、单出口、每部分可达 |
| 顺序结构 | A 执行完必然接着执行 B 的最简单结构 | §2.5.3 | — |
| 选择结构 | 按条件 p 选择执行 A 或 B 之一，两路汇合于单一出口 | §2.5.3 | 注意「判断框两出口」≠「选择结构两出口」 |
| 循环结构 | 反复执行某一部分操作；分当型（while）与直到型（until） | §2.5.3 | 当型先判断后执行；直到型先执行后判断 |
| 当型循环 | 条件 p 成立时执行循环体，执行后再判断，直到 p 不成立为止 | §2.5.3 | 对应 while；可能一次都不执行 |
| 直到型循环 | 先执行循环体，再判断 p，p 不成立则继续执行，直到 p 成立为止 | §2.5.3 | 对应 do…while；至少执行一次 |
| 结构化程序设计 | 强调程序设计风格与结构规范化，用自顶向下、逐步细化、模块化、结构化编码保证结构化 | §2.6 | 是「方法」而非「语法」；核心是控制复杂度 |
| 自顶向下，逐步细化 | 先把问题分成几大部分（顶层设计），再逐层细化直到不需再分 | §2.6 | 与「自下而上、逐步积累」相对 |
| 模块化设计 | 把大任务分为若干子任务（模块），模块间耦合愈少愈好；C 中用函数实现 | §2.6 | 量化约束：单模块一般不超过 50 行 |
| 结构化编码 | 把已细化的算法用计算机语言正确表示出来 | §2.6 | 编码是最后一步，前面必须先有算法 |
| 数据结构 | 程序中用到哪些数据，以及这些数据的类型和组织形式 | §2.1 | 与「算法」并列构成程序；不只是「数据的集合」 |
| 常量 | 程序运行过程中其值不能被改变的量 | §3.2.1 | 分整型/实型/字符/字符串/符号常量五类 |
| 符号常量 | 用 #define 指令指定一个符号名代表一个常量 | §3.2.1 | 预编译后就被替换掉，**不占存储单元**，不能赋新值 |
| 常变量 | 用 const 定义的变量：有类型、占存储单元，但不允许改变其值 | §3.2.1 | 与符号常量的关键差异：常变量**占**存储单元，符号常量不占 |
| 变量 | 一个有名字的、具有特定属性的存储单元；运行期间值可改变 | §3.2.1 | 变量名本质是「一个名字代表的存储地址」 |
| 标识符 | 用来对变量、符号常量名、函数、数组、类型等命名的有效字符序列 | §3.2.1 | 只能由字母/数字/下划线组成，首字符须为字母或下划线 |
| 数据类型 | 对数据分配存储单元的安排，包括存储单元长度与数据的存储形式 | §3.2.2 | 不是「分类标签」，而是决定占几字节、怎么存 |
| 转义字符 | 以反斜杠 \ 开头的字符序列，把后面的字符转换成另外的意义 | §3.2.1 | 如 \n 里的 n 不代表字母 n，而代表换行 |
| 关系表达式 | 用关系运算符连接两个数值或数值表达式而成的式子，值为真(1)或假(0) | §4.3.2 | 值是逻辑量，不是数值本身 |
| 逻辑表达式 | 用逻辑运算符（&&、\|\|、!）连接关系表达式或其他逻辑量而成的式子 | §4.4.2 | 存在「短路求值」：a&&b 中 a 为假就不算 b |
| 条件表达式 | 形式为「表达式1?表达式2:表达式3」；? 是 C 唯一的三目运算符 | §4.5 | 可替代「对同一变量赋值的 if-else」 |
| 复合语句 | 用一对花括号括起来的若干语句，在语法上视为一个语句 | §4.2.2 / §5.2 | 与「语句块」同义；if/while 的内嵌语句常用它 |
| 数组 | 一组有序数据的集合；元素同类型，用数组名加下标唯一确定 | §6.1 | 「有序」指有下标次序，不是「已排序」 |
| 下标 | 表示数组元素在数组中序号的整数；**从 0 开始** | §6.1.2 | a[10] 有元素 a[0]..a[9]，不存在 a[10] |
| 数组初始化 | 定义数组时用「初始化列表」给元素赋初值 | §6.1.3 | 未指定的元素自动为 0（字符数组为 '\0'，指针数组为 NULL） |
| 字符串结束标志 | C 规定以字符 '\0' 作为字符串的结束标志 | §6.3.4 | 字符数组存字符串时必须留位置放 '\0' |
| 函数 | 用来完成一定功能的模块；function 兼有「函数」与「功能」两义 | §7.1 | 「函数就是功能」，函数名应反映其功能 |
| 形参（形式参数） | 定义函数时函数名后括号中的变量名 | §7.3.2 | 未发生调用时不占存储单元，调用时才临时分配 |
| 实参（实际参数） | 调用函数时函数名后括号中的参数，可为常量/变量/表达式 | §7.3.2 | 必须有确定的值 |
| 虚实结合 | 函数调用时实参的值传递给形参的过程 | §7.3.2 | 是**单向值传递**，形参改变不影响实参 |
| 值传递 | 只由实参传给形参、不能反向传递的数据传递方式 | §7.3.3 | 要带回结果须传指针（地址） |
| 函数声明 | 把函数名、类型、参数个数与类型通知编译系统，以便调用时正确识别与检查 | §7.4 | 与「函数定义」不同：声明只需原型，定义要有函数体 |
| 递归调用 | 在调用一个函数的过程中又直接或间接地调用该函数本身 | §7.6 | 必须有限次，靠 if 设置终止条件；分「回溯」「递推」两阶段 |
| 局部变量 | 在函数内定义的变量，只在本函数范围内有效 | §7.8 | 不同函数中同名局部变量互不干扰 |
| 全局变量 | 在函数之外定义的变量，在整个源程序文件范围内有效 | §7.8 | 一直占用存储单元，应尽量少用 |
| 存储类别 | 变量的存储方式（auto/static/register/extern），决定生存期与作用域 | §7.9 | 与「数据类型」是两个维度：类型管怎么存，存储类别管存多久、谁能见 |
| 指针 | 地址的形象化称呼；「指针就是地址」，通过它能找到以它为地址的内存单元 | §8.1 | 物理实现是地址；不是「一种变量」 |
| 指针变量 | 专门用来存放另一变量地址的变量；也可称地址变量，它的值是地址 | §8.1 / §8.2 | 与「指针」严格区分：指针是地址（值），指针变量是变量 |
| 基类型 | 定义指针变量时必须指定的、该指针所指向数据的类型 | §8.2.2 | 决定指针加减 1 移动几字节；int*、float*、char* 是不同类型 |
| 带类型的地址 | C 的地址不仅含位置（纯地址），还含所指向数据的类型信息 | §8.1 / §8.9 | 区别于「纯地址」；正因如此指针必须有基类型 |
| 直接访问 | 按变量名直接存取变量 | §8.1 | 编译器经变量名→地址的对应表定位 |
| 间接访问 | 把地址存进另一变量，再经它找到目标变量并访问 | §8.1 | 指针的本质用法；* 是间接访问运算符 |
| 取地址运算符 & | &a 表示变量 a 的地址 | §8.2.3 | 与「按位与」的 & 同形不同义，看上下文 |
| 指针运算符 * | *p 代表指针变量 p 所指向的对象 | §8.2.3 | 与「乘号」同形不同义；定义时的 * 只是标记该变量为指针 |
| 空指针 NULL | 值为 0 的指针，明确不指向任何变量；系统保证该单元不作他用 | §8.9 | 与「未赋值的指针」不同：NULL 是合法有值状态，未赋值是脏值 |
| 结构体 | 由不同类型数据组成的组合型数据结构；其他语言中称「记录」 | §9.1 | 类型不占空间，变量才占空间；不能对类型赋值 |
| 共用体 | 几个不同类型成员共享同一段存储单元的构造类型 | §9.5 | 同一时刻只有一个成员有效；不能引用共用体变量本身，只能引用成员 |
| 枚举类型 | 用 enum 声明、取值限于所列枚举常量的类型 | §9.6 | 枚举元素按常量处理，有整数值，不能对其赋值 |
| typedef | 为已有类型起一个新名字（不是定义新类型） | §9.7 | 是「起别名」，不是「造类型」 |
| 链表 | 用指针把若干结点串起来的动态数据结构；结点含数据域与指针域 | §9.4 | 结点用 malloc 动态分配；尾结点 next 置 NULL 作遍历终止 |
| 文件 | 一般指存储在外部介质上数据的集合；操作系统以文件为单位管理数据 | §10.1.1 | 分程序文件与数据文件；本章主讲数据文件 |
| 流（stream） | 输入输出是数据传送过程，数据如流水般从一处流向另一处，故称流 | §10.1.1 | 「流」是传输通道，不是数据本身 |
| 流式文件 | C 把文件看作字符（字节）序列，存取以字符为单位，行的界限由程序控制 | §10.1.1 | 两行数据间不会自动加分隔符 |
| 文本文件（ASCII 文件） | 每个字节存放一个字符的 ASCII 代码的文件 | §10.1.3 | 便于逐字符处理，但占空间多、需转换时间 |
| 二进制文件（映像文件） | 内存数据不加转换直接输出到外存的文件，是内存数据的映像 | §10.1.3 | 省空间、省转换时间，但不能直接用文本编辑器读 |
| 文件缓冲区 | 系统在内存为每个在用文件开辟的缓冲区域，装满才与磁盘交换 | §10.1.4 | 正因如此，不 fclose 可能丢数据 |
| 文件类型指针（文件指针） | 指向 FILE 类型（文件信息区结构体）的指针变量 | §10.1.5 | 不是指向磁盘文件开头，而是指向**内存中的文件信息区**开头 |
| 文件读写位置标记 | 每个数据文件自动设置的隐式标记，指向当前读写位置，读写后自动后移 | §10.2.1 脚注 / §10.3 | 理解顺序读写与随机读写的关键 |
| EOF | 文件尾标志，在 stdio.h 中被定义为 -1 | §10.3.1 | 不是文件里真存了一个 -1 的字节，只是一种处理方法 |
| feof 函数 | 检测文件尾标志是否已被读取过；已读出则值为真(1)，否则为假(0) | §10.3.1 | 注意别把 feof 的函数值(1/0)与 EOF 的假设值(-1)混淆 |
| 缓冲文件系统 | ANSI C 采用的文件处理方式：系统自动为每个在用文件在内存开辟缓冲区 | §10.1.4 | 与「非缓冲文件系统」相对 |
