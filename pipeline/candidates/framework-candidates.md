  summary: |

    ①问题分析：忽略次要因素、把问题抽象成数学模型（建立模型）；
    ②设计算法：选出解题方法和具体步骤，一般用流程图表示；
    ③编写程序：按算法用高级语言写出源程序；
    ④编辑、编译、连接：得到可执行程序；
    ⑤运行并分析结果：结果对不代表程序对，要调试（debug）与测试（test）；
    ⑥编写程序文档：程序名称、功能、运行环境、输入数据、注意事项。
    关键洞察在⑤：调试只证明「这一组数据对」，测试要设计多组数据去「尽量发现漏洞」。

  title: 结构化程序设计四步法（自顶向下、逐步细化、模块化、结构化编码）
  type: framework
  source_chapter: 第2章 §2.6 结构化程序设计方法
  source_quote: |
    "具体说，采取以下方法来保证得到结构化的程序：（1）自顶向下；（2）逐步细化；（3）模块化设计；（4）结构化编码。"
    "结构化程序设计方法的基本思路是：把一个复杂问题的求解过程分阶段进行，每个阶段处理的问题都控制在人们容易理解和处理的范围内。"
  summary: |
    面对复杂问题，不做「自下而上、提笔就写」，而是自顶向下逐层分解：先顶层设计（分成几大块），
    再一层层细化（第2层、第3层……直到不需要细分为止）。
    每向下一层展开之前先检查本层是否正确——「只有上一层是正确的才能向下细化」，
    于是整体正确性由每层的局部正确性累加保证。
    模块化设计是把子任务划成相互独立的模块（C 里用函数实现），模块间耦合越少越好。
    最后结构化编码：用只含三种基本结构的语言把算法写成程序。
  inputs: 一个难以一次写清的复杂任务
  outputs: 层次分明、结构清晰、可验证的结构化程序
  steps: [自顶向下分解, 逐层细化并逐层验证, 模块化划分(低耦合), 结构化编码]

  title: 把「逐条罗列」改写成「循环」的算法归纳法
  type: framework
  source_chapter: 第2章 §2.3 简单的算法举例（例2.1、例2.2）
  source_quote: |
    "这样的算法虽然是正确的，但太烦琐。如果要求1×2×…×1000，则要写999个步骤，显然是不可取的。"
    "请读者通过这个简单的例子学会怎样归纳解题的规律，把具体的问题抽象化，设计出简明的算法。"
  summary: |
    当一组操作「每次内容和方法都相似、只是对象不同」时，就把它抽象成循环：
    ①找出每次操作中不变的规律；②用一个变量（下标 i）代表变化的对象；
    ③把重复的操作写成循环体，用控制 i 的变化覆盖全部对象。
    例2.1 把「1×2、再×3、再×4…」改写成 t=t*i; i=i+1; 的循环；
    例2.2 把「检查第1个、第2个…第50个学生成绩」改写成对 g[i] 的循环。
    判据：如果写完发现步骤数与数据量成正比地膨胀，就该找规律改循环。
  inputs: 一串结构相似、仅对象不同的重复操作
  outputs: 用循环变量 + 循环体表达的简明算法
  steps: [识别重复规律, 选循环变量代表变化对象, 写成循环体, 设定终止条件]

- id: f04
  title: 算法表示工具的选型与递进
  type: framework
  source_chapter: 第2章 §2.5 怎样表示一个算法
  source_quote: |
    "为了表示一个算法，可以用不同的方法。常用的方法有：自然语言、传统流程图、结构化流程图和伪代码等。"
    "流程图适于表示一个算法，但在设计算法过程中使用不是很理想（尤其是当算法比较复杂、需要反复修改时）。为了设计算法时方便，常用一种称为伪代码的工具。"
  summary: |
    五种表示法各有适用阶段，按「设计时 / 交付时」分工选用：
    ①自然语言——通俗易懂但冗长、易生歧义，只适合最初口述思路；
    ②传统流程图——直观、能暴露逻辑错误，但不限流向易画成「一碗面条」，且修改麻烦；
    ③N-S 结构化流程图（盒图）——去掉流程线、强制结构化，紧凑易画，适合表示最终算法；
    ④伪代码——介于自然语言与编程语言之间，书写/修改最方便，适合算法设计过程中反复改；
    ⑤计算机语言——唯一能被计算机执行的表示。
    实务建议：设计阶段用伪代码快速迭代，定稿用 N-S 图或流程图核对结构，最后翻译成程序。
  inputs: 一个待表达的算法
  outputs: 选定表示法下的算法描述，可过渡到程序
  steps: [设计期用伪代码迭代, 定稿用N-S图/流程图核对结构, 翻译为计算机语言]
  missing_conditions: 无
  tags: [framework, algorithm-representation, flowchart, pseudocode]

- id: f05
  title: 三种基本结构组合法（顺序 / 选择 / 循环）
  type: framework
  source_chapter: 第2章 §2.5.3 三种基本结构和改进的流程图
  source_quote: |
    "1966年，Bohra 和 Jacopini 提出了以下3种基本结构，用这3种基本结构作为表示一个良好算法的基本单元。"
    "由以上3种基本结构顺序组成的算法结构，可以解决任何复杂的问题。"
  summary: |
    任何复杂算法都能由三种基本结构嵌套组合而成，这是结构化程序设计的基石：
    ①顺序结构——A 执行完必然接着执行 B；
    ②选择结构——按条件 p 走 A 或 B 之一，两路汇合于单一出口（注意：判断框有两个出口，但选择结构只有一个出口）；
    ③循环结构——当型（while：先判断后执行）与直到型（until：先执行后判断）两种。
    三种结构共同特点：只有一个入口、只有一个出口、结构内每一部分都有机会被执行到。
    用法：拿到问题先判断它属于「顺序 / 分支 / 重复」哪一类，再用对应结构拼装；
    发现算法无法分解成这三种结构，就说明它不是结构化的，需要改造（见 f06）。
  inputs: 任意待结构化的算法
  outputs: 仅由三种基本结构嵌套组成的结构化算法
  steps: [判定问题属于顺序/选择/循环, 用对应基本结构表达, 嵌套组合, 校验单入口单出口]
  missing_conditions: 无
  tags: [framework, structured-programming, control-structure]

- id: f06
  title: 非结构化算法改造法（引入标志变量收敛多出口）
  type: framework
  source_chapter: 第2章 §2.5.4 用 N-S 流程图表示算法（例2.15 素数判断）
  source_quote: |
    "图2.12不是由3种基本结构组成的。图中间的循环部分有两个出口……不符合基本结构的特点。由于不能分解为3种基本结构，就无法直接用N-S流程图……来表示。因此，应当先对图2.12作必要的变换。"
    "w 的作用如同一个开关一样，有两种工作状况：w=0 和 w=1……当w=1时表示被检查的数n为非素数。"
  summary: |
    当循环体内出现「提前跳出」导致一个结构有多个出口时，用标志变量把它收敛成单出口：
    ①设一个「开关」变量（如 w，初值0）；②把原本要「立即跳出」的情形改成「置开关为1」；
    ③把开关纳入循环条件（如 i≤√n 且 w==0），循环自然退出；
    ④循环后再用选择结构根据开关值决定输出。
    这样就把「两个出口的循环」变成「单出口的当型循环 + 一个后续选择」，从而可拆成三种基本结构。
    这是一个通用的「把非结构化跳转结构化」的手法。
  inputs: 含提前跳出、多出口的非结构化算法
  outputs: 单入口单出口、可分解为三种基本结构的等价算法
  steps: [识别多出口点, 引入标志变量代替跳出, 将标志并入循环条件, 循环后按标志分支]

- id: f08
  title: 指针的「间接访问」心智模型
  type: framework
  source_chapter: 第8章 §8.1 指针是什么
  source_quote: |
    "由于通过地址能找到所需的变量单元，可以说，地址指向该变量单元……因此，将地址形象化地称为'指针'。"
    "这种直接按变量名进行的访问，称为'直接访问'方式。还可以采用另一种称为'间接访问'的方式，即将变量i的地址存放在另一变量中，然后通过该变量来找到变量i的地址，从而访问i变量。"
  summary: |
    建立指针概念的推理链（作者认为讲清这条链，指针就不难）：
    ①内存在编译时按变量类型分配若干字节，每个字节有编号＝地址（相当于旅馆房间号）；
    ②通过地址能找到变量单元，故「地址指向该单元」，把地址形象地叫「指针」；
    ③直接访问＝按变量名直接存取；间接访问＝先把地址存进另一个变量，再经它找到目标；
    ④专门存放地址的变量叫「指针变量」，它的值是地址；
    ⑤关键：C 的地址是「带类型的地址」——不只有位置（纯地址），还带所指向数据的类型信息，否则不知道该按几个字节、按什么方式取数。
    配套两个运算符：& 取地址、* 解引用（间接访问）。
    一句话：指针就是地址；指针变量是存地址的变量。
  inputs: 一个变量及其地址
  outputs: 通过指针变量间接读写该变量的能力
  steps: [理解地址=房间号, 区分直接访问与间接访问, 掌握带类型的地址, 使用&与*]
  missing_conditions: 无
  tags: [framework, pointer, memory-model, mental-model]

  title: 文件读写的「打开—读写—关闭」流程
  type: framework

- id: f10
  title: 程序调试与测试的分工
  type: framework
  source_chapter: 第1章 §1.6 程序设计的任务（第5阶段）
  source_quote: |
    "调试的过程就是通过上机发现和排除程序中故障的过程。……不要只看到某一次结果是正确的，就认为程序没有问题。……所谓测试，就是设计多组测试数据，检查程序对不同数据的运行情况，从中尽量发现程序中存在的漏洞。"
  summary: |
    把「让程序看起来能跑」拆成两个不同目标的活动：
    ①调试（debug）：针对已知的失败，定位并排除故障——目标是「修好这个问题」；
    ②测试（test）：主动设计多组（含边界）数据，目的是「尽量发现还没暴露的漏洞」——目标是「找出问题」。
    作者用 c=b/a 举例：a=4,b=2 得 0.5 正确，但 a=0 就崩——单组数据通过不能证明程序正确。
    判据：只跑通一组数据就交付＝没做测试。
  inputs: 一个能运行但正确性未知的程序
  outputs: 已排除故障、并对多组数据验证过的程序
  steps: [复现并定位故障(调试), 设计多组含边界数据, 运行比对, 修补后回归]
  missing_conditions: 无
  tags: [framework, debugging, testing, quality]
