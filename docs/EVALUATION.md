### 断言的修正记录（审计用）

首轮断言有 5 条过窄，误伤了**更通用/更规范**的正确写法，已修正：

1. o1 的 `%4`、`%100`、`%400` 用 `contains` → 答案写成 `year % 4`（带空格）被判失败。改为正则 `%\s*4`。
2. o2 的 `<9`、`<9-j` 硬编码书中的 n=10 → 答案用 `N-1`、`N-1-j`（更通用）被判失败。改为 `(9|N\s*-\s*1)` 形式。
3. o2 的 `a[i+1]`、`t=a[i]` 死绑变量名 → 答案用 `a[j+1]`、`t=a[j]`（i/j 角色互换）被判失败。改为下标变量名无关的正则。
4. o5 的 `int\s+\w+\(\s*int` 死绑 `int` 返回类型 → 答案用 `long long`/`unsigned long long`（更能防溢出，更好）被判失败。改为 `(int|long long|unsigned long long)`。

修正方向统一为「语义等价即通过」，不降低正确性要求。

## 三、输出质量（匿名 A/B 语义盲评）

机械断言只能证明「两边的代码都正确」，无法区分质量高低，故补一步 A/B：把两变体答案随机标为 A/B（映射表对评审隐藏），交独立 agent 按「正确性 > 解释到位 > 边界意识 > 可读性」排序判胜。

| case | 胜者 | 对应变体 | 理由摘要 |
|---|---|---|---|
| o1-leap | A | **new_skill** | 逐层量化推导 + 400 年 97 闰 / 146097 天交叉验算 + 7 组用例 |
| o2-bubble | B | **new_skill** | 9 趟逐行状态追踪表；抓住「if 三条语句漏花括号」「内外层变量同名」两个致命坑 |
| o3-swap | B | without_skill | 同一程序内跑出「内部已交换 / 调用后没变」对比；陷阱覆盖更全 |
| o4-oob | B | **new_skill** | 把「起点 1」与「上界 <=10」拆成两个独立错误；点出「定义时 a[10] 是长度、引用时是第 11 个元素」 |

## 四、结论（不夸大）

1. **触发精度是这套产物的真实优势**：71 条用例上 F1 = 1.000、兄弟混淆 0。对比之下，泛化型模型并不知道「该用哪张卡」，这个能力是技能包独有的。
2. **单题输出质量与强基线持平**（机械断言 6:6，A/B 3:3）。这是一条**反向发现**，不应被包装成"技能让模型变强"：当用户提问已经足够具体时，一个能力足够的通用模型也能写出同样正确的 C 代码。
3. **技能包的真实价值在另外三处**：
   - **可发现性**：不知道问什么、怎么拆问题时，卡片提供结构化入口；
   - **一致性**：不同问题都按同一套方法（先算法、再结构、再边界）作答，不靠临场运气；
   - **边界自觉**：卡片 B 段强制声明"本书不适用什么"（C11+、构建系统、所有权模型、数据库），避免把教学代码当工程方案。这一点在 A/B 中体现为 new_skill 版本更常主动划界。
4. **未做的部分**：`old_skill` 变体（首次发布无旧版）；多轮 `runs=3` 采样（当前每用例单次）；validation 集（各能力 3–5 条）未单独做最终验收。因此本报告的数字是**单次采样**结果，不代表统计意义上的稳定性。

# 附录二：独立题集验收（第三轮，破除循环）

## 为什么还要再做一轮

前两轮 holdout 有个共同缺陷：**题目和描述都是同一个作者写的**。即使换措辞，作者也会不自觉地写出「刚好匹配自己描述」的题，这就是前几轮收敛到 1.000 的机制性原因。这是自证，不是验证。

## 做法

1. **出题完全不看描述**：让一个 sub-agent 只被告知「这是谭浩强 C 语言教材，覆盖哪些主题」，不给任何 skill 描述、不给 evals 目录、不给卡片内容。要求它扮演中国大一学生写 20 条「真的会去问」的问题，其中 10 条明确、6 条模糊跨主题、4 条应超范围。
2. **答案是事后标注**：标注由主流程做（这一步仍有作者主观性，但**题目内容**是独立的）。对模糊题设 `accept_also` 白名单，不苛求唯一答案。
3. **3 次采样**：同一题集交 3 个独立 agent 各跑一遍，测稳定性。

## 结果

| run | 最优命中 | 可接受/可达 | 未命中 | 最优率 | 可达率 |
|---|---|---|---|---|---|
| run1 | 17/20 | 3 | 0 | 85.0% | 100% |
| run2 | 19/20 | 1 | 0 | 95.0% | 100% |
| run3 | 19/20 | 1 | 0 | 95.0% | 100% |
| **均值** | | | | **91.7%** | **100%** |

**稳定性**：20 条中 **18 条三次完全一致**，2 条有波动：

| case | 题目 | 三次选择 |
|---|---|---|
| q09 | `Segmentation fault` 崩了，不告诉哪一行，怎么查 | pointer-model / program-skeleton / program-skeleton |
| q13 | 跑十次有七八次对，偶尔蹦出离谱的数 | reference / program-skeleton / program-skeleton |

这两条波动**不是 bug，是题目本身处在灰区**：都是「崩溃/偶发错误」类问题，横跨 `pointer-model`（野指针）、`program-skeleton`（三类分诊）、`debug-and-test`（怎么查）三个能力。真人问这种问题本来也不会有唯一正确答案，判成任何一个都说得通。

## 一个反向发现

q09、q13 这两条最贴 `debug-and-test` 的题，**三次没有一次选中 `debug-and-test`**——都被 `program-skeleton` 的分诊入口接走了。这不是错误（`program-skeleton` 的 description 明确写了「运行时错（越界/野指针）的三类分诊」），但说明：`debug-and-test` 作为独立主题**几乎不会被主动选择**，它的职能被 `program-skeleton` 吸收了。这印证了当初把它定为 router 而非 promoted 的判断是对的。

## 停止调优的理由

按方法论，这里**必须停手**。如果我现在再根据这 2 条波动去改描述，这批独立题集就变成第四批「被看过的调优集」，又退化成自证。

所以本轮结果**如实封存**，不再据此修改任何 description。

## 三轮验证的最终结论

| 阶段 | 数据 | 最优率 | 可达率 | 性质 |
|---|---|---|---|---|
| 首轮 | 71 条（作者自写） | F1 1.000 | — | **过拟合**，不可作为泛化证据 |
| 二轮 | holdout-1 23 条 | 87.0% | — | 未见数据，暴露 2 个真缺陷 |
| 二轮 | holdout-2 16 条 | 93.8% | 100% | 未见数据，修复后 |
| **三轮** | **独立题集 20 条 × 3 采样** | **91.7%** | **100%** | **题目内容独立，最可信** |

**最终可宣称的数字**：
- **最优路径命中率 ≈ 91.7%**（用户问题会被直接送到最合适的能力）
- **最终可达率 = 100%**（即使没送到最优入口，也一定能到达正确的能力卡）
- **逐题稳定性 18/20 = 90%**（剩下 2 条是真实的语义灰区）

**不能宣称的**：任何高于 91.7% 的最优率；任何"质量提升"（A/B 3:3 平局）。
