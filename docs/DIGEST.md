## 这本书在讲什么

这本书要解决的问题很具体：**怎么让一个没学过编程的大学生，在不被语法劝退的前提下，真正学会用 C 写程序，并建立正确的程序设计思想。**

它的答案不是"把 C 语言讲全"，而是反过来——把语言当工具，把程序设计当目的。作者在每一章都坚持同一条路线：先讲清要解决什么问题、怎么设计算法，再把算法翻译成代码，最后分析程序、指出新手常错的地方。所以这本书的顺序不是"语法由简到繁"，而是"能解决的问题由简到繁"。

这个选择的结果是：它成了一本发行超过 1400 万册的教材，也成了很多人对 C 的第一印象。但它同时有明确的时代烙印——基于 C99，示例环境是 Visual C++ 6.0 / VS2010，不涉及构建系统、测试框架、并发与内存所有权模型。读它要有取舍：**把它当作"程序设计入门的方法论"，而不是"现代 C 工程手册"。**

下面按书本身的骨架展开，每个方法论都说明它解决什么问题、逻辑是什么、书中怎么用、什么时候会失效。

## 一、先有算法，再写代码

这是全书最贯穿的一条主张，也是它区别于"语法手册"的根本。

作者把"做一道编程题"拆成六个阶段，其中**前两个阶段完全不碰代码**：问题分析（忽略次要因素、把问题抽象成模型）→ 设计算法（选出方法和步骤，用流程图或伪代码写下来）→ 编写程序 → 编辑编译连接 → 运行并分析结果 → 写文档。

那为什么必须先设计？因为面对复杂问题时，人不可能一次性想清楚所有细节。所以要用**自顶向下、逐步细化**：先做顶层设计（这问题分几大块），再一层层往下分，直到每一小块都能直接写成几条语句。关键在于，**每向下一层展开之前，先检查本层对不对**——只有上层正确才往下细化，于是整体正确性由每层的局部正确性累加保证，而不必一次性扛住全部复杂度。

细化到一定粒度，就把每个子任务做成独立模块（C 里就是函数）：一个模块只干一件事，模块间耦合越少越好，单个模块不超过约 50 行。这就是分而治之。

算法用什么记下来？三个工具分阶段用：**伪代码**最快（加一行删一行都不费事，适合设计期反复改）；**N-S 图**（盒图）没有流程线、上下顺序就是执行顺序，适合定稿核对结构；**传统流程图**直观、能暴露逻辑错误，但不限流向，容易画成"一碗面条"，且改动麻烦。

还有两个最常用的具体手法，值得单独记住：

**把"逐条罗列"改写成"循环"**。当一组操作每次内容相似、只是对象不同时，就该抽象成循环：找出不变的规律、用一个变量代表变化的对象、让这个变量遍历全部。判据很朴素——如果你写完发现步骤数随数据量成正比膨胀，就该找规律。书中例 2.1 求 5!，最初写法是"1×2 得 2，再 ×3 得 6，再 ×4…"，作者直接指出：求 1×2×…×1000 要写 999 步，"显然是不可取的"。

**用标志变量收敛多出口**。当一个循环里有"提前跳出"，导致这个结构有两个出口，它就不再是结构化的。办法是设一个开关变量（`w`，初值 0），把"立即跳出"改成"置开关为 1"，再把开关并入循环条件，循环自然退出，最后用选择结构按开关值输出。书中例 2.15（素数判断）就是靠这个把画不出 N-S 图的算法改造成了结构化的。

> "引导读者在处理任务时先考虑算法再编程，而不是坐下来就写程序，养成良好的编程习惯。"

**什么时候会失效**：当需求本身还没定型时（边写边发现要什么）。此时强行自上而下会设计出错误的结构，正确做法是先做原型验证需求，再回来正式设计。

## 二、三种基本结构就是全部积木

1966 年 Bohra 和 Jacopini 提出：任何复杂算法都能由三种基本结构嵌套组合而成。

- **顺序**：A 执行完必然接着执行 B；
- **选择**：按条件走两支之一，**两路汇合于单一出口**；
- **循环**：当型（先判断后执行）与直到型（先执行后判断）。

判定一个算法是否"结构化"的标准只有三条：单入口、单出口、结构内每一部分都存在一条从入口到出口的通路（没有永远执行不到的"死块"）。

这里有一个极易混淆的点，值得单独拎出来：**判断框确实有两个出口，但选择结构整体只有一个出口。** 这两件事说的不是一回事。

在写控制语句时，选型逻辑是这样：

**选择**——两个分支，或分支条件是范围／复合条件，用 `if`（`if…else if…else` 链适合多档范围判断）；多分支且每支对应离散常量（等级字符、菜单命令），用 `switch`，它一次比较就跳到对应标号，比多层嵌套 if 清晰。特殊情况：if 和 else 都是给同一个变量赋值，可压成 `(a>b)?a:b`。

**循环**——进入前就该判断、可能一次都不执行，用 `while`；至少执行一次，用 `do…while`；三要素（初值／条件／增量）清晰、次数确定，用 `for`。书中例 5.3 专门对比了 while 与 do…while：输入 `i=11` 时，while 一次也不执行（sum 保持 0），而 do…while 仍执行一次（sum=11）。作者结论是"当 while 后面的表达式的第1次的值为'真'时，两种循环得到的结果相同；否则，二者结果不相同"。

**提前走**——`break` 终止整个循环，`continue` 只结束本次。

## 三、程序骨架与"错误在哪一步"的导航图

一个 C 程序的骨架是固定的：`#include`（要用标准输入输出就 `#include <stdio.h>`）＋`int main()`＋`return 0;`。其余全部内容都是往这个骨架里加东西。

真正有用的是**四步流水线与错误类型的对应关系**，这是排错的导航图：

| 步骤 | 产物 | 出错时暴露什么 |
|---|---|---|
| 编辑 | `.c` 源文件 | — |
| 编译（预处理＋语法检查） | `.obj` 目标文件 | **语法错误**（缺分号、拼错函数名、变量未定义） |
| 连接（装配函数库） | `.exe` 可执行程序 | `undefined reference` 类（函数未定义／库未链接） |
| 运行 | 运行结果 | **逻辑错误**（公式错、赋值方向反、边界未处理） |

所以看到一个错误，先问它在哪一步出现。编译报错就去改语法；能编译但结果错就去查逻辑。作者还强调一个容易被忽略的事实：**即使只有一个源文件，也必须经过连接**，因为它要与函数库装配。

## 四、数组：用下标换掉重复，用 0 基换掉混乱

要处理"一批同类型数据"，用 N 个独立变量是错的——不但定义繁琐，而且这堆变量之间没有内在联系，无法统一遍历。数组解决的就是这个：一个共同的名字 + 下标区分彼此，于是可以配合循环批量处理。**数组 + 循环**，一套代码处理任意多个元素。

用数组必须刻在脑子里的四件事：

1. **下标从 0 开始**。`int a[10]` 的合法下标是 0~9，**不存在 `a[10]`**。危险在于 C 不做越界检查（作者在第 1 章就明说"对数组下标越界不进行检查，由程序编写者自己保证程序的正确"），越界不报错，只会悄悄改坏相邻内存。安全模板只有一个：长度 N，遍历一律 `for(i=0;i<N;i++)`。
2. **长度必须是常量表达式**。`int a[n]`（n 是变量）在本书所依据的经典 C 里不合法。
3. **初始化有默认规则**。给了长度并做了初始化，未覆盖的元素自动为 0（字符数组为 `'\0'`，指针数组为 `NULL`）。全 0 只需写 `int a[10]={0};`。
4. **字符串是"以 `'\0'` 结尾的字符数组"**。它没有长度字段，靠结尾那个 `'\0'` 标记结束。所以存 n 个字符至少要 n+1 个位置；忘了放 `'\0'`，用 `%s` 输出就会一直往后读到撞上内存里的某个 0——这就是"输出一串乱码"的成因。

**排序是数组最典型的应用**，也是双重循环的经典范式。起泡法的思路：每趟把当前未排好部分的最大数"沉底"，共 n-1 趟，第 j 趟只需比较 n-j 次。所以内层上界随外层变量递减——这个"内层上界依赖外层"的写法是双重循环的关键技巧，写错就变成多余比较或漏比较。

## 五、函数：参数传递是 C 最容易被误解的一点

理解函数最省力的方式不是背定义，而是把"函数"当成"一段有名字的功能"。`function` 在英文里既是"函数"也是"功能"，这个双关正是它的本质：函数名就是给某个功能起的名字，而一个函数只应该干一件事。

定义函数要交代四件事：名字、返回值类型、参数的个数与类型、函数做什么。如果定义在调用点**之后**，调用前必须先**声明**——告诉编译器"有这么个函数、它是什么规格"。这就是"定义"与"声明"的区别：定义有函数体、给了实现；声明只是原型。

**参数传递是全章最容易踩的坑。** 调用函数时，系统把实参的**值**复制给形参，二者占不同存储单元。因此函数内怎么改形参都改不到实参——这叫**单向值传递**。想通过函数修改调用者的变量，必须传**地址**（指针），在函数里通过 `*p` 改目标单元。

数组是个"例外中的例外"：数组名作实参时传过去的是**首元素地址**，不是整个数组的副本，所以函数内改数组元素会影响原数组。这看起来像"传引用"，实质仍是值传递——只不过传的"值"是地址。这一点最容易被当成"值传递失效"。

**递归**是把大问题化成同型小问题的写法，必须有**两部分**：递归关系（n 的问题 = n-1 的同类问题 + 一步操作）和**终止条件**（基例，到某个值直接给答案）。执行分两阶段：先"回溯"（一路展开到基例），再"递推"（从基例结果一层层回代）。

递归不是万能的。凡是递归能写的，循环加数组也能写。递归的优势在于有些问题用循环表达极其别扭——比如 Hanoi 塔，64 个盘子的移动序列直接写几乎不可能，但"假设 63 个已经能搬"之后，三步就描述完了。判断该不该用递归，看问题是否天然同构地降阶，而不是看它"看起来高级"。

> "实参向形参的数据传递是'值传递'，单向传递，只能由实参传给形参，而不能由形参传给实参。"

**什么时候会失效**：函数体只有一两行且只调用一次时，抽成函数反而增加阅读跳转成本。50 行是上限，不是要求把所有东西都拆碎。

## 六、指针：把"地址"和"类型"两层分开，就不难了

指针之所以难，是因为它同时涉及两层东西：**地址**（一个位置编号）和**该位置存的是什么类型的数据**。把这两层分开，整章就通了。

**第一层：地址。** 每个变量在编译时被分配几个字节，每个字节有编号，这个编号就是地址——相当于旅馆的房间号。通过房间号能找到房间，所以说"地址指向该单元"，把地址形象地叫做"指针"。这就是全书最核心的一句：**指针就是地址**。

访问变量有两种方式：**直接访问**是按变量名存取（编译器内部有"变量名→地址"的对应表）；**间接访问**是先把地址存进另一个变量，再经它找到目标——那个"专门存地址的变量"就是**指针变量**。

**第二层：类型。** 光有地址不够。告诉你"从 2000 号单元取数据"，你仍不知道该取 1 个字节（字符）、2 个字节（短整型）还是 4 个字节（整型），也不知道按补码还是按浮点解释。所以 C 的地址是**带类型的地址**：它不只是位置，还包含"指向的数据是什么类型"。这就是为什么定义指针必须指定**基类型**——它决定 `*p` 读几个字节、按什么格式解释，也决定 `p+1` 往后移 1 字节还是 4 字节。

由此推出：`*p` 代表"p 所指向的那个变量"，既能读也能写（`*p=3` 是把 3 存到 p 指向的单元，不是把 3 存进 p）；而 `p` 本身的值是地址，改 `p` 只是改变"指向谁"。

**三个必须严格分开的概念**：指针＝地址（一个值）；指针变量＝存地址的变量；基类型＝它指向什么类型。所以可以说"变量 i 的指针是 2000"，但不能说"i 的指针变量是 2000"——指针变量是 p 本身。

**安全用法只有一条铁律：用之前先让它指向合法对象。** 指针定义后不赋值，它的值是内存残留垃圾，此时 `*p = 3` 会随机改坏无关内存。必须区分三态：未赋值（脏值，危险）／值为 `NULL`（明确不指向任何对象，合法可判断）／指向有效对象（唯一可解引用的状态）。

书中用一组绝妙对照说明 `p` 与 `*p` 的差别：例 8.2 交换两个指针的**指向**，a、b 的值并没有交换（仍是 5 和 9），但输出 `*p1`、`*p2` 得到 9 和 5；例 8.3 传指针进 swap 函数，改的是 `*p1`、`*p2`，a、b 真的交换了。同一个"交换"，一个换指向、一个换值。

> "作者明确指出'指针就是地址'。很多读者反映，这是画龙点睛，把指针讲透了，抓住了问题的本质。"

**什么时候会失效**：这套"地址＝房间号"的讲法对理解 `&`/`*` 极有效，但不涉及所有权、生命周期、悬垂指针（free 后继续用）、别名与优化。真实工程中的内存问题，需要另找材料。

## 七、结构体与文件：把数据组织成实体，再让它活过进程

**结构体**解决的是"一组不同类型但有内在联系的数据"。一个学生的学号、姓名、性别、年龄、成绩、地址属于同一个人，用 6 个互不相干的变量存，丢掉了"它们属于同一个实体"这个信息；数组也不行，因为数组只能装同一类型。结构体的关键区分是：`struct Student` 是**类型**（样板，编译时不占空间），`struct Student s1` 才是**变量**（占空间、能存取）。

结构体最有价值的用法是**自引用结构**——成员可以是指向自身类型的指针。这正是链表的根基：每个结点有数据域和指针域，用指针把分散的结点串起来，于是长度可以在运行期增长、插入删除不必整体搬移。链表三条要点：结点用 `malloc` 逐个分配；尾结点的 `next` **必须置 `NULL`**，这是遍历的终止标志；遍历写 `for(p=head; p!=NULL; p=p->next)`。

**文件**解决的是"数据要活过进程"。C 把文件看成一串字符（字节）的序列，按字符为单位存取，行的界限由程序控制——这叫流式文件。操作固定三步：

1. **打开** `fopen(文件名, 方式)`，返回指向该文件**内存信息区**的指针（注意不是指向磁盘文件开头）。方式 `r`／`w`／`a` 决定只读／覆盖写／追加，加 `b` 表示二进制方式（不做换行转换）。**打开后必须检查是否返回 `NULL`**。
2. **读写**。按粒度分四种：字符（`fgetc`/`fputc`）、字符串、格式化（`fscanf`/`fprintf`）、数据块（`fread`/`fwrite`）。系统用一个隐式的**文件读写位置标记**记录当前位置，读完自动后移；读完最后一个字符后再读得到 `EOF`（-1）。
3. **关闭** `fclose(fp)`。这一步最容易被当成可有可无，但它才是保证落盘的关键。

为什么必须关闭？因为写文件时数据先进入内存缓冲区，**缓冲区满才真正写盘**。不关闭就结束程序，缓冲区里没满的那部分就丢了。`fclose` 的动作正是"先把缓冲区刷到磁盘，再撤销信息区"。

## 八、跑通不等于正确：调试与测试是两件事

"程序能跑起来"和"程序是对的"是两个完全不同的判断。这本书把它们拆成两个目标相反的活动：

- **调试（debug）** 针对**已知的失败**——报错了、结果不对了，去定位并排除。目标是"修好这一个问题"。
- **测试（test）** 针对**未知的漏洞**——程序看起来正常，主动设计多组数据去撞它。目标是"发现问题"，不是"证明没问题"。

为什么这个区分重要？因为人的默认心态是"跑通了就是对的"。作者用了一个极简例子打掉这个幻觉：`c=b/a`，取 a=4、b=2 得到 0.5 完全正确；但取 a=0 就没法算了。同一份代码，一组数据对、另一组数据错——所以**一组数据通过不能证明程序正确**。

因此必须主动构造多组数据，特别是**边界值**：0、1、负数、数组的第一个和最后一个元素、循环一次都不执行的情形、刚好达到上限的情形。

## 陷阱与反例

作者反复警告的失败模式，挑杀伤力最大的几条：

**1. 用 `a=b; b=a;` 交换两值。** 直觉上"把 a 给 b、把 b 给 a"就是交换，但赋值是覆盖：执行 `a=b` 后 a 的原值已销毁，再执行 `b=a` 只是把 b 的值又赋回 b，最后两个变量都等于原来 b 的值。必须借第三个变量：`t=a; a=b; b=t;`。

**2. 数组下标从 1 开始 / 访问 `a[n]`。** 循环写成 `for(i=1;i<=10;i++) a[i]=i;` 同时犯了两个错——漏掉 `a[0]`、并写到不存在的 `a[10]`。而 C 不检查越界，所以不报错，只悄悄破坏内存。**预警信号**：首元素永远是 0／空、程序偶发崩溃、别的变量莫名改变。

**3. 循环体缺"让循环结束"的语句。** 只写了 `i<=100` 却忘了在循环体里改变 i，条件永远为真。**预警信号**：程序不结束、CPU 占用高、屏幕重复刷同一条内容。

**4. 循环体多条语句漏花括号。** `while`／`for` 的"语句"只涵盖紧随其后的一个语句。本意两条却没加 `{}`，则只有第一条属于循环。**预警信号**：循环次数对但累加结果错、某条语句只执行一次。

**5. 忘记给累加器／循环变量赋初值。** 它们的值是内存残留垃圾，sum 的初值可能不是 0。**预警信号**：多次运行结果不同、累加结果莫名偏大、循环一次都不执行。

**6. `switch` 的 case 漏 `break`。** 匹配到某个 case 后只是"跳转到该标号"，之后一路往下执行，不再逐个比较。书中例 4.6 明确说：漏 break 会"连续输出 85～100 / 70～84 / 60～69 / <60 / enter data error!"——一次输入、五条输出。

**7. 野指针。** 定义 `int *p;` 后 p 里是随机地址，此时 `*p=3` 会读写一块完全无关的内存。注意**"未赋值"≠"值为 NULL"**：NULL 是明确不指向任何对象的合法状态，未赋值是脏值。**预警信号**：随机崩溃、不相干变量莫名改变、换一次运行表现不同。

**8. `else` 的悬空配对。** C 规定 else 与"离它最近且尚未配对的 if"配对，**与缩进无关**。想让 else 属于外层 if，却因为内层 if 没有 else 而被它抢走。

**9. `scanf` 忘记 `&`。** scanf 需要知道"把数据送到哪里"，要的是地址。漏掉 `&` 时它把变量的当前值当地址用，写入随机内存。**预警信号**：输入后变量值不变、程序崩溃。

**10. 输入 double 却用 `%f`。** 输入时 double 必须用 `%lf`；用 `%f` 只写入 4 字节，高 4 字节保留垃圾。**预警信号**：输入的浮点数读出来是天文数字或 0。

**11. 不 `fclose` 就结束程序。** 缓冲区未满的数据丢失。**预警信号**：文件内容比预期少，小数据量时尤其明显。

**12. 字符串常量误用单撇号。** 单撇号是字符常量（只能装一个字符），双撇号才是字符串。把 `"boy"` 写成 `'boy'` 属于多字符常量，值是实现定义的。

**13. 递归缺终止条件。** 只写了"n 化为 n-1"却没写"n 到什么值直接返回"，递归一直展开到栈溢出。

**14. 混淆结构体"类型"与"变量"。** 对类型赋值／取成员是非法的——类型只是样板，不占空间。

## 作者的局限（读这本书要打的折扣）

只报喜不报忧的精华是软文，不是蒸馏。这本书至少有以下几点需要在读的时候自觉打折：

**1. 标准偏旧。** 基于 C99，未覆盖 C11/C17/C23 的新特性（`_Generic`、线程、标准化原子等）；示例环境是 Visual C++ 6.0 / VS2010，在现代编译器（GCC 13+、Clang）下部分老示例会报错或给出警告。书中明说 `int a[n]`（n 为变量）不合法，但 C99 起已引入变长数组——按现代标准回答这类问题必须说明差异。

**2. 不涉工程实践。** 没有构建系统（Makefile/CMake）、版本控制、单元测试框架、静态分析、sanitizer、调试器进阶用法。书中的"测试"停留在"手工设计数据、逐组运行比对"的黑盒层面。

**3. 示例是教学规模。** 作者自己说"本教材中的例题程序的规模一般都不大"。没有多文件项目、接口契约设计、真实数据规模下的性能与健壮性考量。

**4. 部分内容已外移。** 第 5 版把「位运算」「预处理指令」「常见错误分析（35 种）」「C 程序应用案例」移到了配套的《C程序设计（第五版）学习辅导》一书。正文并不完整覆盖这些主题——这一点在买书时就该知道。

**5. 指针讲法有效但有限。** "地址＝房间号"这套比喻对理解 `&`/`*` 极好，但不涉及内存所有权、生命周期、悬垂指针、指针别名与优化限制（`restrict`、严格别名）。真实工程的内存问题需要另找材料。

**6. 链表只作简介。** 作者前言明确说这部分"对非计算机专业学生来说，难度较大"，正文只作简单介绍，双向链表、循环链表、删除结点、逆转链表等都在习题与辅导书里。

**7. 立场上的取舍。** 为降低门槛，作者刻意只讲"够用就好"的语法子集。这可能让读者误以为 C 就是书里这点。作者自己也提醒"不应当局限于教材中的内容"——但教材的边界就在那里。

## 如果只带走三句话

1. **先算法，后代码。** 拿到任务先问"分几步、每步做什么"，而不是先敲 `int main`。
2. **指针就是地址，地址带类型。** 记住这一句，加上"用前必须指向合法对象"，指针的八成困惑会消失。
3. **跑通不等于正确。** 一组数据通过什么都不能证明；必须测边界。
