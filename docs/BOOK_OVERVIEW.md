## 1. 结构 (Structural)

### 类型
实操型入门教材 + 语法参考。以"由浅入深、循序渐进、实例驱动"为编排原则，而非纯理论方法论书。

### 一句话主旨
用尽量少的语法概念、配合大量可运行实例，把零基础读者带到一个能独立写出结构化 C 程序、理解指针与文件的程度。

### 骨架 (主要论点及其关系)

1. **程序与算法基础**（第1–2章）：先建立"什么是程序、什么是算法"的元认知，再用流程图/N-S图把算法可视化。
2. **三种控制结构**（第3–5章）：顺序、选择、循环——结构化程序设计的全部积木，递进关系。
3. **批量数据与模块化**（第6–7章）：数组解决"一批数据"，函数解决"一段逻辑复用"，并列但互补。
4. **指针与自定义类型**（第8–9章）：指针是 C 的灵魂也是难点；结构体/共用体/枚举/typedef 让数据组织更贴近问题。
5. **文件**（第10章）：把程序从"内存临时计算"扩展到"持久化 IO"。

**论点之间的关系**: 递进 + 并列混合——控制结构是基础能力，数组/函数并行扩展，指针/自定义类型是进阶，文件是外围能力。

### 作者要解决的核心问题
"中国高校零基础学生如何在不被语法劝退的前提下，真正学会用 C 语言写程序、并建立正确的程序设计思想。"

## 2. 解释 (Interpretive)

### 关键术语 (作者本人的用法)

| 术语 | 作者的定义/用法 | 和常识用法的差异 |
|---|---|---|
| 算法 | 对特定问题求解步骤的描述（广义：做什么+怎么做） | 不只是"数学公式"，包括流程 |
| 结构化程序 | 由顺序/选择/循环三种基本结构构成的程序 | 强调"单入口单出口"的模块 |
| 指针 | 用来存放变量地址的变量 | 初学者易与"变量本身"混淆 |
| 数组 | 有序数据的集合，用下标访问 | 强调"同类型、连续存放" |
| 函数 | 实现特定功能的独立程序模块 | 强调"模块化、可复用" |

### 核心命题 (用自己的话)
1. 程序设计 = 算法 + 数据结构（程序 = 算法 + 数据）。
2. 任何复杂程序都能由三种基本控制结构组合而成（结构化程序设计）。
3. 好的程序先有清晰算法，再写代码——"先想清楚，再写"。
4. 指针是 C 高效与灵活的来源，也是绝大多数 bug 的来源。
5. 通过"运行—观察—改错"的循环来学习，比死记语法更有效。

### 论证链
作者用"先概念后实例、每章末尾排错/常见错误"的螺旋方式：提出结构 → 给最小可运行例子 → 扩展语法 → 指出新手常错点 → 综合例题。

## 3. 批判 (Critical) ★

### 作者的时代局限
- 第5版基于 C99 之前/早期标准，未覆盖 C11/C17/C23 的现代特性（如 `_Generic`、线程、标准化原子等）。
- 示例偏"教学玩具"，缺少真实工程规模与多文件项目、构建系统、测试。
- 未涉及现代工具链（ sanitizers、静态分析、版本控制）。

### 作者的立场盲点
- 为降低门槛，强调"够用就好"的语法子集，可能让读者误以为 C 就是书里这点。
- 对指针的"风险面"着墨于报错现象，较少从内存模型/所有权角度系统讲解。

### 未被证明的假设
- 假设读者主要在 Turbo C / 早期环境（部分示例依赖旧头文件如 `<stdio.h>` 的古老写法，但第5版已改 `void main` 等）。
- 假设"多写例子就能会"，弱化抽象建模训练。

### 最强反对意见
- 现代教学更推荐从一开始就建立内存模型与调试习惯，而非先堆语法例子；
- 该书风格偏"语法手册+例题"，对"如何 decompose 真实问题"的方法论相对薄弱。
